# 수어 지문자 미니게임 사용법

브랜치: `feature/sign-fingerspelling` · 기준 커밋 `d006ab4` · 작성 2026-11-26
계획서: [`Sign-Fingerspelling-Plan.md`](Sign-Fingerspelling-Plan.md)

> 현재 상태: 게임 흐름(소개 → 연습 → 도전 → 결과)과 녹화 도구는 완성됐고 Unity 컴파일·단위 테스트는 통과했다. **실제 웹캠 실기는 아직 미검증**이고, 정식 글자 5개(P0)와 녹화 데이터가 아직 없다. 아래 순서대로 임시 손 모양으로 먼저 시험해 본다.

## 1. 빠른 시작 (임시 손 모양으로 5분 시험)

1. Unity 6000.3.23f1로 프로젝트를 열고 `feature/sign-fingerspelling` 브랜치인지 확인한다.
2. **Play**를 누른다. 게임의 시선 추적·사진 촬영이 웹캠을 쓰고 있으면 먼저 끈다.
3. 상단 메뉴 **Tools → Sign → Recorder**로 녹화 창을 연다.
4. 녹화 설정
   - **사람 ID (가명)**: 예 `tester1`
   - **세션 ID**: 예 `s1`
   - **글자 목록 (쉼표 구분)**: 예 `주먹,보자기,검지,_other`
5. **손 추적 시작**을 누르고, 녹화 창의 상태에 손 감지가 표시되는지 본다.
6. 위쪽 선택 칸이나 진행 막대 옆 글자 버튼으로 손 모양을 고르고(선택된 글자에 ▶ 표시), 손 모양을 유지한 채 **시도 녹화 시작**을 눌렀다가 1~2초 뒤 **시도 녹화 종료**를 누른다. 창에 포커스가 있으면 **Space를 누르고 있는 동안** 녹화된다.
   - 손 모양마다 **시도 3회 이상**, `_other`(그 외 손 모양)도 손 펴기·흔들기·다른 모양으로 3회 이상 녹화한다.
   - 유효 프레임이 10개 미만이면 "너무 짧음"으로 저장되지 않는다.
7. **손 추적 종료** → Play를 멈춘다.
8. `Tools/SignData/raw/tester1/s1.csv`를 `Assets/StreamingAssets/SignData/`로 복사한다.
9. 다시 Play → **미니게임 → 하이라이트 → 수어 지문자**.
10. **연습 시작** → 화면의 글자를 따라 한다. 0.6초 유지하면 정답 처리되고 다음 글자로 넘어간다. 연습이 끝나면 도전(글자당 8초)과 결과가 나온다. 결과 화면에서 **다시 하기**로 순서를 바꿔 다시 할 수 있다.

## 2. 게임 화면 설명

| 영역 | 내용 |
|---|---|
| 왼쪽 | 웹캠 미리보기(거울처럼 좌우 반전), 손 관절 21개 점과 뼈대 |
| 오른쪽 위 | 단계(소개·연습·도전·결과), 제시 글자, 남은 시간, 교수 대사(사회복지학과 백소담 교수) |
| 오른쪽 가운데 | 글자별 점수 막대(k-NN 이웃 투표 비율, 확률 아님), 유지 게이지(0.6초) |
| 아래 | 처리 시간(ms), 모델 `k-NN`, 실행 장치 `CPU` |
| 참고 그림 | `Assets/Resources/Sign/<글자>.png`가 있으면 표시, 없으면 "참고 그림 준비 중" |
| 디버그 보기 | 감지 시간 평균·최대·중앙값, FPS, MediaPipe 왼손/오른손 원시 값, 거리 상한과 계산 시간 |

도전 모드에서 다른 글자로 인식되면 "다시 해 보세요 (○○로 보였어요)"가 나오고 제한 시간 안에 계속 시도할 수 있다. 시간이 지나야 오답 처리되며 결과에 틀린 시도 수가 남는다.

## 3. 예외 상황

| 상황 | 동작 |
|---|---|
| `StreamingAssets/SignData`에 CSV가 없음 | "학습 데이터 없음" 안내, 웹캠을 켜지 않음 |
| 카메라 없음·권한 거부 | 안내 + **카메라 없이 보기**(참고 그림 넘겨 보기) |
| 모델 생성 실패 | 안내 + **돌아가기** |
| 웹캠 시선 추적 중 진입 | "시선 추적을 끄면 보정이 초기화됩니다" 확인. 끄고 들어왔다면 나갈 때 **보정하러 가기** 안내 카드 |
| 카메라 90/270도 회전 | 지원하지 않음 안내 |

## 4. 녹화 도구 세부

- 저장 위치: `Tools/SignData/raw/<사람 ID>/<세션 ID>.csv` (Git 제외)
- 저장 항목: 사람·세션·시도·글자·프레임·시각·프레임 크기·왼손/오른손 원시 라벨·점수·관절 21개 좌표(x, y, z). **영상·이미지는 저장하지 않는다.**
- 저장하지 않는 프레임: 관절이 21개가 아니거나, 값이 비정상이거나, 왼손/오른손 판정이 없거나, 프레임 크기가 0인 경우(건너뜀 수 표시)
- 저장은 임시 파일에 쓴 뒤 교체한다. 실패하면 데이터를 메모리에 남겨 **다시 저장**으로 재시도할 수 있다(**보관 시도 버리기**로 포기).
- **마지막 시도 삭제**: 방금 저장한 시도만 지운다.
- 기존 CSV의 헤더나 줄 형식이 틀리면 추가·삭제를 하지 않고 줄 번호를 안내한다.
- 같은 에디터에서 녹화 창을 두 개 열면 두 번째 창은 녹화가 막힌다.
- **녹화 전 참여자 동의를 받는다**(계획서 6.2절).

## 5. 정식 데이터로 갈 때 (계획서 7절)

1. **P0**: 한국수어사전 영상으로 지문자 5개 확정, 가능하면 검수.
2. 5명 이상, 글자당 사람별 15회 이상, 조명 2종 이상, 다른 날 한 번 더. 1명은 최종 평가용으로 빼 둔다.
3. 녹화 파일을 `Assets/StreamingAssets/SignData/`(하위 폴더 가능)에 둔다. 좌표 CSV의 Git 커밋 여부는 팀이 정한다.
4. 거리 상한은 데이터에서 자동 계산된다(같은 글자·다른 시도 표본 간 최근접 거리의 95백분위 × 1.5, 하한 0.05). 디버그 보기에서 값을 확인한다. **어느 글자든 서로 다른 시도가 2개 미만이면 계산하지 않고 상한 없이 동작한다**(디버그 보기에 "거리 상한 계산 불가(시도 부족)"). 그래서 글자마다 시도를 3회 이상 녹화한다.

## 7. 미검증 항목

- 실제 웹캠에서 관절 위치 정렬, 왼손/오른손 판정의 거울 기준(`SignLabelsAreMirrored`, 현재 false)
- 녹화 도구의 실기 녹화·저장·삭제
- 표본 1만~2만 개일 때 게임 진입 시간
- 학교 PC 성능(감지 시간, 갱신률)
- Python 전처리 일치 테스트(이 PC에 Python 없음)
