# 눈맞춤 횟수 카운터

## 플레이 방법 (팀원용)

1. 타이틀에서 학과와 교수를 고른다.
2. `시선 추적 준비` 화면에서 `노트북 웹캠` 또는 `iPhone 추적`을 고른다(다음 실행 때 기본값으로 기억).
   - 웹캠: `웹캠 시작` → 얼굴이 잡히면 `화면 맞춤 (16점)` → 화면의 점을 차례로 바라본다(약 30초).
   - iPhone: VTube Studio Wi-Fi/USB 연결 → 16점 보정. 연결 방법은 `docs/AI/iPhone-Gaze-Tracking-Setup.md`.
3. 보정이 끝나면 스토리가 자동으로 시작된다. 평소처럼 플레이하면서 교수 얼굴을 바라보면 횟수가 쌓인다(화면에는 안 보임).
4. 엔딩 화면 통계 아래 `눈 마주침 N회`로 결과가 나온다.
- 확인용: 에디터에서 F8을 누르면 판정 영역과 `눈맞춤 N`, 증가 순간 `+1`이 보인다.
- 이어하기도 매번 보정한다. `준비 취소`를 누르면 새 게임은 교수 선택, 이어하기는 타이틀로 돌아간다.
- 웹캠이나 iPhone이 없으면 스토리를 시작할 수 없다(필수 보정).
- 시선 이탈 끼어들기 확인: 아래 조건과 확률을 기다리거나 개발용 F9로 바로 확인한다.

## 동작

- 새 게임은 교수 선택 직후, 이어하기는 저장 데이터를 불러온 직후 시선 추적 준비 화면을 연다. 보정이 끝나기 전에는 스토리를 진행하지 않는다.
- 장치는 웹캠 또는 iPhone 중 선택하며 `GazeTest.EyeContactDevice` PlayerPrefs 값을 다음 실행의 기본 선택으로 쓴다.
- 웹캠 준비에서는 UnitEye 1단계 보정을 생략하고 16점 화면 맞춤만 수행한다. 1단계 생략으로 정확도가 낮아질 수 있지만 눈맞춤 횟수는 경향성을 보는 목적이므로 이를 수용한다. iPhone은 기존 Wi-Fi/USB 연결 화면과 13개 맞춤점 + 3개 검증점 보정 흐름을 그대로 사용하며, 이전 보정값으로 필수 보정을 건너뛰지 않는다.
- 일반 시선 추적 테스트 메뉴의 웹캠은 기존 1단계 UnitEye 보정 → 16점 화면 맞춤 흐름을 유지한다.
- 준비 화면의 취소는 새 게임이면 교수 선택으로, 이어하기면 타이틀의 학과 선택으로 돌아간다. 이어하기 취소는 저장 데이터를 바꾸지 않는다.
- 준비를 통과하면 보정기와 추적 객체를 유지하고, 테스트 화면을 닫은 채 장면 1~6의 시선 좌표를 갱신한다. 엔딩, 타이틀 복귀, 앱 종료에서 기존 정리 경로로 장치를 닫는다.
- 엔딩에는 추적 준비를 통과한 경우에만 `눈 마주침 N회`를 표시한다. 총 응시 시간은 세이브 데이터에 저장하고 이어하기 시 복원하지만 엔딩 통계 줄에는 노출하지 않는다.
- 다른 게임 시스템에서 사용할 값은 `EyeContactCount`, `EyeContactTotalSeconds`, `EyeContactTrackingEnabled` 읽기 전용 속성으로 노출한다. 카운터 자체는 호감도나 엔딩 계산에 쓰지 않지만, 아래 시선 이탈 이벤트는 호감도를 낮춰 기존 엔딩 계산에 반영한다.
- 추적 준비 화면과 기존 시선 테스트 메뉴는 같은 UI/보정 로직을 공유한다. 연습 모드와 `Story.ResolveEnding` 인자는 바꾸지 않았다.

## 판정 규칙 및 조정 상수

상수는 `GameController.EyeContact.cs`에 모여 있다.

| 항목 | 기본값 | 설명 |
|---|---:|---|
| 연속 응시 | 0.45초 | 진입 타원 안에 연속으로 머물면 1회 증가 |
| 재진입 대기 | 0.3초 | 한 번 센 뒤 나가기 타원 밖에서 이 시간 동안 유효하게 응시해야 다시 센다 |
| 얼굴 타원 반지름 | 얼굴 크기 × 1.4 | 가로·세로 배율은 별도 상수 |
| 나가기 타원 | 진입 타원 × 1.25 | 경계 흔들림에 대한 히스테리시스 |
| 얼굴 미등록 이미지 추정 | 사각형 상단 18%, 높이의 20% | 상반신·전신·기본 초상화 사각형 기준 |
| 초상화 최소 alpha | 0.5 | 그 이상 표시될 때만 판정 |
| 프레임 시간 상한 | 0.1초 | 긴 프레임 정지로 가짜 응시가 더해지는 것을 제한 |

`PortraitFaces` 등록 이미지는 얼굴 중심과 크기를 사용한다. 그 밖의 초상화는 실제로 그린 사각형을 현재 `GUI.matrix`와 캔버스 행렬로 변환한 뒤 근사 얼굴 위치를 계산한다. 듀오 초상화의 이동·축소도 그리는 행렬을 통해 반영한다.

유효 시선이 없거나, 교수 얼굴이 표시되지 않거나, 초상화 alpha가 기준 미만이거나, 메뉴·미니게임·연습·스킵 중이면 응시 진행을 초기화한다. 깜빡임 중에는 응시와 이탈 진행을 멈춘다. 누적 응시 시간은 유효 시선이 진입 타원 안에 있는 동안만 증가한다.

## 시선 이탈 끼어들기

### 동작

- 눈맞춤 세션이 켜진 스토리에서만 판정한다. 일반 대사와 교수 초상화가 함께 보일 때 유효한 시선이 나가기 타원 바깥에 연속 7초 머물면 이탈 1건이다.
- 선택지가 보이는 동안, 퀴즈 또는 AI 입력·응답 대기 중, 선택 결과(`showResult`) 중, 챕터 카드가 보이는 동안에는 판정하지 않는다. 메뉴, 미니게임, 연습, 스킵/Ctrl, 준비 중, 깜빡임, 교수 얼굴 미표시, 무효 시선 등 기존 기록 제외 상태도 적용한다.
- 이탈마다 25% 확률로 한 줄 끼어든다. 실패하면 메뉴 시간을 제외한 60초 뒤 다시 판정한다. 스토리 플레이 시간이 90초가 되기 전에는 판정하지 않는다.
- 발동하면 교수의 `LookAwayLine`을 이름표와 함께 표시하고 Frown 표정 및 기존 `Down` 효과음을 쓴다. 호감도는 1 감소하며 기존 `TrackAffection` 팝업과 엔딩 계산에 반영된다.
- 끼어들기 대사는 대화 기록, `ReadLog`, 스킵 판정에 추가하지 않는다. 닫으면 원래 줄의 대사와 타자기 진행 상태로 돌아간다. 이탈 끼어들기는 한 판에 최대 1회이며 새 게임에서 초기화하고, 발동 여부는 저장·이어하기에 유지한다. 읽기 전용 속성은 `LookAwayTriggered`다.

### 조정 상수

`GameController.EyeContact.cs`의 눈맞춤 상수 옆에 둔다.

| 항목 | 기본값 | 설명 |
|---|---:|---|
| 이탈 연속 시간 | 7초 | 나가기 타원 바깥에 연속으로 머무는 시간 |
| 발동 확률 | 25% | 이탈 1건마다 한 번 판정 |
| 실패 후 쿨다운 | 60초 | 메뉴를 제외한 플레이 시간 기준 |
| 스토리 최소 플레이 시간 | 90초 | 준비 완료 후, 메뉴를 제외한 플레이 시간 기준 |

### 플레이 방법

시선 추적 준비를 마친 뒤 90초 이상 플레이하고, 교수 얼굴이 보이는 일반 대사 중 얼굴 바깥을 7초 넘게 바라본다. 매 이탈마다 25% 확률로 끼어들며, 선택지·퀴즈·AI 입력·결과·챕터 카드와 기존 기록 제외 상태에서는 발생하지 않는다.

### 개발 키

Unity Editor 또는 Development Build에서 F8 디버그 표시를 켜면 기존 상태 패널 아래에 이탈 연속 시간, 실패 쿨다운, 발동 여부가 한 줄로 나온다. F9는 시선, 시간, 확률, 쿨다운을 무시하고 현재 스토리 화면에서 즉시 발동시키며 실제 발동 플래그와 호감도도 반영한다. 두 키와 표시 코드는 Release 빌드에 포함되지 않는다.

## 개발용 표시

Unity Editor 또는 Development Build에서 F8을 눌러 디버그 표시를 켜거나 끈다. 분홍색은 진입 타원, 보라색은 나가기 타원, 점은 현재 시선 좌표다. 좌상단 상태 패널에 횟수·누적 응시 시간·현재 판정 상태를 표시하고, 타원 위에는 굵은 `눈맞춤 N` 카운터를 표시한다. 증가 순간부터 0.6초 동안 `+1`이 카운터 옆에서 위로 이동하며 사라진다. 타원 위 카운터는 캔버스 안쪽으로 클램프한다. Release 빌드에서는 이 입력과 렌더 경로가 컴파일되지 않는다.

카운트가 증가할 때 Unity Console에 `[eye contact]`와 장면, 플레이 시간, 누적 횟수를 한 줄로 기록한다.

## 저장 호환성

횟수, 누적 초, 추적 사용 여부와 시선 이탈 발동 여부를 기존 PlayerPrefs 슬롯 문자열 뒤에 선택 필드로 추가했다. 누락된 필드는 0/false로 읽으므로 이전 저장도 계속 불러올 수 있다. 이어하기는 저장된 통계를 복원한 뒤 매번 필수 보정을 다시 요구한다.

## 설계 결정 및 검증 범위

- 기존 보정 구현은 맞춤 13점과 별도 검증 3점을 포함해 총 16점을 측정하므로 이를 그대로 재사용한다. 화면에 별도 보정기를 복제하지 않았다.
- 이어하기 준비를 취소하면 기존 세이브를 유지한 채 타이틀로 돌아간다. 이어하기에는 교수 선택 단계가 없으므로 이 경로를 사용한다.
- 웹캠 준비에서 UnitEye 1단계를 생략했을 때의 정확도 영향과 경향성 목적에 충분한지는 실제 기기 측정 전이라 미검증이다. 자동 보정 성공, 추적 세션 유지, 저장 호환성, 판정 영역의 실기기 좌표도 Unity Editor/기기에서 확인하지 않았다. 프로젝트 지정 PowerShell 테스트 결과는 코드 변경 후 작업 인수인계에 기록한다.
- Unity 전체 컴파일, 웹캠/iPhone 연결, 눈맞춤 판정의 화면 좌표 정확도와 실제 플레이 동작은 미검증이다.
