# 컴퓨터공학과 주제 선택형 강의·AI 전공 퀴즈 시범

## 적용 범위와 진입 위치

시범 대상은 컴퓨터공학과의 심한뫼·이명희 교수뿐이다. 4장 오피스아워 첫 슬롯(`Slots[6]`, stage 0)의 기존 퀴즈 자리에 `MiniGameKind.Lecture`를 연결했다. 기존 대화는 빈 검색 결과를 상담하는 장면이므로, 마지막 교수 대사를 기초 복습 주제 선택으로 자연스럽게 이어지도록 한 줄만 고쳤다.

슬롯 4는 다음 슬롯이 반복문 미니게임이라 연속 미니게임이 되고, 슬롯 10은 발표 전날 프로젝트를 마무리하는 장면이라 강의와 덜 맞는다. 슬롯 6은 오피스아워에서 기초를 되짚는 흐름에 맞고 다음 슬롯이 일반 선택지여서 적절하다. 이 슬롯은 정답 시 관심도 `i`를 올린다.

**플레이 방법:** 타이틀 → 공학부 → 컴퓨터공학과 → 교수 선택 → 4장 오피스아워에서 강의 도전. 또는 타이틀 → 미니게임 연습 → 공학부 → 컴퓨터공학과 → 강의. AI 모드를 켜고 키를 사용할 수 있으면 문제와 오답 맞춤 해설이 교수 말투로 생성된다.

연습 메뉴는 스토리 슬롯의 `Game` 목록을 나열한다. 컴퓨터공학과에 미니게임이 네 개라 기존 카드보다 작은 타일로 표시해 난이도·교수 선택과 겹치지 않게 했다. 다른 학과의 메뉴와 게임은 바뀌지 않았다.

## 구현 구조

- `Assets/Scripts/LectureProblems.cs`: Unity에 의존하지 않는 `LectureProblems.Generate(topic, experienced, Random)` 생성기, 정답·보기·오답 착각 및 입력 정규화, AI 문제 응답 검증.
- `Assets/Scripts/Stories/Engineering/AiSwLectures.cs`: 세 주제의 이름·짧은 설명·학습 요점, 교수별 5줄 강의, 교수 반응.
- `Assets/Scripts/LectureQuiz.cs`: 주제 선택, 타자 효과 대화, 보기/직접 입력, 결과, AI 작업 폴링을 맡는 `MiniGame` 파생 클래스.
- `Assets/Scripts/MiniGames.cs`: `Lecture` 종류와 팩토리 등록. `GameController`는 스토리·호감도·AI 모드 정보를 넘기고, 기존 `Done/Delta/Replies` 결과 흐름을 그대로 사용한다.
- `Assets/Scripts/AiProfessor.cs`: 기존 `Persona`를 이용해 문제·맞춤 오답 해설 프롬프트를 만들고 `Clean`으로 응답을 정리한다.
- `Assets/Scripts/Stories/Engineering/AiSwStory.cs`: 슬롯 6을 강의로 연결하고 통계를 `i`로 지정한다. `AiSwQuizzes.cs`의 `SearchMajor`, `SearchMinor` 정의와 `Find()`는 보존했다.

## 코드가 정답을 만드는 규칙

보기 네 개와 정답은 전부 코드가 만든다. AI는 문제 문장과 풀이 문장만 제안하며 답이나 보기를 바꾸지 못한다. 오프라인에서도 주제별 문제 템플릿 3종과 풀이 템플릿 2종으로 같은 데이터의 문제를 바로 보여 준다.

| 주제 | 코드가 만드는 입력과 정답 | 오답 유형 |
|---|---|---|
| 자료구조 | 1~9의 서로 다른 값 3~5개, 스택/큐, 꺼내는 횟수 k. LIFO/FIFO 규칙으로 k번째 값을 계산한다. | 반대 구조, 처음/마지막 삽입값, 다음 값, k를 값으로 착각 |
| 알고리즘·비전공자 | 서로 다른 수 7~15개를 정렬하고 목록 내 target을 고른다. 순차 탐색 비교 횟수는 target의 인덱스+1이다. | 이진 탐색 횟수, 0부터 세기, ±1, 목록 길이 |
| 알고리즘·전공자 | 같은 생성 규칙의 정렬 목록에서 이진 탐색을 수행한다. 양끝 포함 `lo/hi`, `mid=(lo+hi)/2` 내림 규칙으로 target을 찾은 비교 횟수를 센다. | 순차 탐색 횟수, 0부터 세기, ±1, 목록 길이 |
| 컴퓨터 기초·비전공자 | 4~5비트 2진 문자열에서 켜진 자리값을 더해 10진수 정답을 만든다. | 비트 뒤집기, 자리값 빠뜨리기/추가, 1의 개수를 값으로 착각 |
| 컴퓨터 기초·전공자 | 10~63의 10진수를 만들고 정확한 2진 문자열을 계산한다. 앞자리 0과 공백은 무시한다. | 비트 뒤집기, 자리값 빠뜨리기/추가, 1의 개수를 값으로 착각 |

전공자 숫자 입력은 공백과 앞자리 0을 지운 뒤 숫자 문자열로 비교한다. 컴퓨터 기초 전공자는 2진 문자열의 공백과 앞자리 0을 지운 뒤 비교한다. 잘못된 문자는 답으로 인정하지 않는다.

## AI 프롬프트와 검증

AI 문제 요청은 주제를 고르는 즉시 시작하고 강의 대화 중 대기한다. 문제 시스템 프롬프트에는 기존 교수 페르소나·호감도, 주제와 요점, 입력 숫자, 정답, 네 보기와 각 오답 착각을 전달한다. 응답은 다음 두 줄 형식이어야 한다.

```text
문제: <본문>
풀이: <정답 풀이 1~2문장>
```

검증은 두 라벨의 존재, 각 길이(문제 140자·풀이 160자 이하), 코드 생성 수치 누락, 풀이의 정답 포함, 다른 보기를 정답으로 단정하는 문장을 확인한다. `AiProfessor.Clean`으로 따옴표와 리치 텍스트 표식을 정리한다. 하나라도 실패하면 오프라인 문제 문장과 풀이를 사용한다.

오답일 때만 두 번째 요청으로 정답·학생이 고른 값·그 값에 해당하는 착각을 전달한다. 결과는 오프라인 맞춤 해설로 즉시 열리고, 3초 안에 유효한 AI 해설이 도착하면 해당 문장을 교체한다. 네트워크 작업은 `Draw`에서 완료 여부만 읽으며 게임이 질문/결과를 닫았거나 타임아웃됐으면 응답을 버린다. 한 판에서 생성 요청 1회, 오답 해설 요청 최대 1회로 AI 프롬프트 요청은 최대 2회다. 첫 응답이 강의 뒤에도 오지 않으면 최대 4초 기다린 뒤 오프라인으로 넘어간다.

## 결과·연습

정답은 `Delta=1`, 오답은 `Delta=0`이며 감점은 없다. 결과 전용 화면에서 정답 풀이와 선택한 오답의 착각을 확인하고 닫으면 기존 미니게임 결과 화면으로 돌아간다. 3단계 별 표시 대신 결과 카드만 사용한다. 심한뫼·이명희 각각 `Replies[professor][0..2]` 문구를 두어 인덱스 범위를 보장한다.

## 다른 학과로 확장

1. `LectureTopic`에 주제를 추가하고 `LectureProblems.Generate`에 수치·정답·오답 계산, 입력 정규화, 오프라인 질문·풀이 템플릿을 추가한다. 별도 테스트에서 독립 계산으로 정답을 검산한다.
2. `AiSwLectures`의 이름·설명·요점 및 교수별 강의 줄 배열에 같은 인덱스의 데이터를 추가한다. 새 교수는 4~6줄 분량의 자체 말투 대사를 작성한다.
3. 해당 학과 `Story` 슬롯에 `MiniGameTheme { Kind = MiniGameKind.Lecture, Replies = ... }`를 연결하고, 해당 스토리 교수 수와 맞는 반응 배열 및 적합한 통계를 지정한다.
4. 연습 메뉴에 미니게임이 네 개 이상 생기면 압축 카드 배치와 터치·키보드 입력 위치를 확인한다.

## 검증 및 미검증

`Tests/LectureProblems.Tests.ps1`은 세 주제 × 전공/비전공 × 각 1,000회(총 6,000회)를 생성해 서로 다른 보기 네 개, 정답 하나, 독립 계산과의 일치, 입력 정규화, AI 응답 정상·거부 사례를 확인한다. 기존 회귀 테스트 다섯 종도 변경 후 실행했다. 다섯 회귀 테스트와 신규 생성기 테스트가 모두 exit 0이고, Unity 6000.3.23f1 배치 컴파일도 exit 0이다. 기존 `AiProfessor.cs` CS0162 및 테스트의 `CoffeeRecipeSO.cs` CS0649 경고가 출력됐다.

미검증: 실제 플레이 화면 배치·키보드/마우스 조작, 실제 AI 응답과 지연·오류 시나리오, 실기기 조작. 배치 컴파일과 단위 테스트는 실제 플레이 흐름을 대신하지 않는다.
