# 움직이는 공 시선 추적 테스트베드

## 사용 방법

1. Unity에서 `Main` 씬을 Play하고 **시선 추적 테스트**를 엽니다.
2. 웹캠 또는 iPhone을 연결하고 해당 장치의 화면 보정까지 완료합니다.
3. 오른쪽 위의 **움직이는 공 · 로그** 버튼을 누릅니다. 연결 전에도 공의 움직임을 미리 볼 수 있습니다.
4. 가로 왕복, 세로 왕복, 타원, 8자, 9점 고정 중 하나를 고릅니다. 주기는 6/10/16초, 기록 시간은 30/60/120초입니다. 9점 고정은 점당 3초입니다.
5. 비교할 코드 버전이나 실험 이름을 오른쪽 입력란에 적고 **3초 후 기록 시작**을 누릅니다.
6. 노란 공만 계속 바라봅니다. 청록 원은 추정 시선이며 점선은 목표와의 차이입니다. 시선 표시를 숨겨도 로그는 계속 기록됩니다.
7. 기록 시간에 도달하면 자동 종료됩니다. 일시 정지, 조기 종료, 로그 폴더 열기도 지원합니다.

## 로그와 실시간 분석

Editor에서는 `Logs/GazeLab/`, 빌드에서는 `Application.persistentDataPath/GazeLab/`에 저장합니다. 외부 서버로 전송하지 않습니다. 영상과 사진은 저장하지 않습니다.

- 세션별 CSV: 렌더링된 프레임의 목표·시선 좌표, 평활화 전 매핑 좌표, 오차, 입력 특징, 프레임/표본 번호, 유효성, 눈 감김, 관측 지연, 화면 크기 등을 기록합니다.
- 세션별 JSON: 장치, 경로, 주기, 실험 이름, 매퍼 계수, 누적 평균/RMSE/P95/편향/유효 표본 비율을 저장합니다.
- `latest.json`: 현재 또는 마지막 세션의 요약과 CSV 경로를 초당 한 번 갱신합니다. 종료 시에도 즉시 반영합니다. `updated_utc`가 오래되면 Editor 일시 정지나 실행 중단 여부를 확인합니다.
- 로그는 읽기 공유 모드로 열기 때문에 실행 중에도 에이전트가 읽을 수 있습니다.

PowerShell에서 최근 15초를 분석합니다. 시스템 실행 정책을 변경하지 않고 이 프로세스에만 스크립트 실행을 허용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Analyze-GazeLab.ps1
# 2초 간격으로 10번 관찰
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Analyze-GazeLab.ps1 -Iterations 10
# 특정 파일 전체를 분석
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Analyze-GazeLab.ps1 -Csv 'Logs/GazeLab/<session>.csv' -WindowSeconds 10000
```

분석 결과에는 전체 오차, 화면 영역별 오차, 가로·세로 추종 상관계수, 고개 방향과 오차의 상관계수가 포함됩니다. `raw_rmse_px`와 `rmse_px`를 비교하면 평활화와 경계 제한을 포함한 표시 단계의 영향을 구분하는 데 도움이 됩니다. 상관관계만으로 원인을 확정해서는 안 됩니다.

## 측정 기준과 한계

- 모든 좌표는 **1280×900 논리 캔버스**, 좌측 상단 원점, 오른쪽/아래쪽 양수입니다. 오차는 `시선 - 목표`입니다. 실제 Game 뷰 픽셀은 캔버스 좌표에 `canvas_scale`을 곱하고 중앙 여백을 더합니다. `screen_width`, `screen_height`는 캡처 당시의 뷰 크기입니다.
- `raw_x/y`는 **매퍼를 통과한 후, 경계 제한과 표시 평활화 전** 좌표입니다. 센서의 원래 입력은 `eye/head/look/position` 열에 따로 저장합니다. 매퍼 드리프트는 raw와 표시 좌표 모두에 이미 포함됩니다.
- 웹캠의 `position_x/y`와 `head_distance_m`는 모델이 제공한 머리의 평행 이동과 거리를 기록합니다. `network_yaw_rad/pitch_rad`는 정밀 모델의 화면 평면 변환 전 시선 각도입니다. 없는 거리 값은 빈 칸이며, iPhone의 위치 단위는 해당 전송 경로의 단위입니다. iPhone에는 웹캠 네트워크 각도가 없어 해당 각도 열은 0입니다.
- 표본 번호가 바뀐 경우만 집계합니다. 끊긴 연결, 얼굴 미검출, 눈 감김, 미보정, 포커스 상실, 일시 정지, 카운트다운, 목표 전환 후 0.7초, 비정상 좌표는 정확도 집계에서 제외합니다. 제외된 행도 CSV에 남습니다.
- 같은 표본으로 반복 그려진 프레임은 최대 초당 약 30행의 상태 기록으로 남지만 정확도 집계에는 중복 반영하지 않습니다. Unity가 한 프레임 사이에 받은 중간 표본은 저장할 수 없으므로 CSV는 센서 전체 패킷 덤프가 아닙니다.
- `elapsed_s`는 포커스가 있는 동안 진행한 실험 시간이며 `realtime_s`는 Unity의 단조 증가 시계입니다. 로그는 `OnGUI`의 Repaint 때 기록합니다. 카메라 노출 시각과 화면 표시 시각을 동기화한 장비 측정은 아닙니다. 움직이는 목표와의 거리는 사람의 추종 지연도 포함합니다. 정적인 편향은 **9점 고정**에서 따로 확인합니다.
- 평가 중에는 별잡기의 자동 앵커 및 pursuit 보정을 호출하지 않고 UnitEye의 온라인 드리프트 보정도 중지합니다. 테스트 화면을 닫으면 기존 온라인 보정 설정을 복원합니다. 매퍼에 기존에 적용된 드리프트는 유지하고 기록합니다.
- `metrics_available=false` 또는 유효 표본 0개는 정확도 0px라는 뜻이 아닙니다.

## 개선 반복 절차

동일 장치·자세·보정·경로·주기로 baseline을 기록합니다. 에이전트가 최근 로그와 영역별 오차를 읽고 가설 하나를 고릅니다. 기록을 종료한 뒤 코드를 수정하고 컴파일하며, 새 실험 이름으로 같은 조건에서 재측정합니다. 기록 도중 코드가 리로드되면 `OnDisable`이 로그를 마무리합니다. 실제 시선 데이터 없이 정확도가 개선되었다고 판정하지 않습니다.

개발 검증은 `Tools > Checks > Gaze Lab` 메뉴로 실행합니다. 경로 범위, 표본 중복 방지, 눈 감김/포커스/미보정/NaN 제외, 소수점 로캘 독립성, 실행 중 CSV 읽기, 최종 JSON 반영을 확인합니다.
