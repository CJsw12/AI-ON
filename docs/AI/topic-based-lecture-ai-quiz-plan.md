# 주제 선택형 강의와 AI 전공 퀴즈 기획서

## 1. 목적

플레이어가 학과 교수와 대화하면서 **배우고 싶은 전공 주제를 직접 선택**하고, 선택한 주제에 맞는 강의 대화와 퀴즈를 경험한다.

기존 프로젝트의 교수 캐릭터, 대화, 전공자·비전공자 난이도, 미니게임 흐름을 활용한다. 1차 버전에서는 주제별 미니게임을 새로 제작하기보다 **AI가 주제에 맞는 전공 퀴즈를 생성**한다.

이 문서는 기획 초안이다. 현재 프로젝트의 정확한 진입 화면과 연결 지점은 구현 담당 에이전트가 코드를 확인한 후 결정한다.

## 2. 플레이 흐름

1. 플레이어가 학과와 교수를 선택한다.
2. 교수 또는 친구가 이번에 배우고 싶은 주제를 묻는다.
3. 플레이어가 3개 내외의 주제 중 하나를 선택한다.
4. 선택한 주제에 맞는 강의 내용이 교수·친구와의 대화에 포함된다.
5. 강의에서 다룬 개념을 바탕으로 AI가 전공 퀴즈를 생성한다.
6. 플레이어가 객관식 답을 선택한다.
7. 교수 또는 친구가 정답과 풀이를 설명한다.
8. 결과를 보여주고 기존 스토리 진행 흐름으로 돌아간다.

주제 선택 결과는 **이후 강의 내용과 퀴즈에 함께 반영**돼야 한다.

## 3. 시범 학과와 루트

첫 시범 범위는 컴퓨터공학 관련 교수 한 명과 다음 3개 주제다.

| 주제 | 강의에서 다룰 예시 | 퀴즈 유형 예시 |
|---|---|---|
| 자료구조 | 스택과 큐의 입출력 방식 | 연산 결과에서 나온 값 고르기 |
| 알고리즘 | 순차 탐색과 정렬된 자료의 탐색 | 조건에 맞는 탐색 과정 이해하기 |
| 컴퓨터 과학 기초 | 이진수와 데이터 표현 | 간단한 2진수·10진수 변환 |

표의 세부 개념은 예시다. 실제 구현 전 각 루트에서 **한 번의 강의가 다룰 개념을 좁혀** 정한다. AI가 강의에서 설명하지 않은 고급 개념을 문제로 요구하지 않도록 한다.

## 4. 플레이 예시

### 자료구조 선택

> **교수:** 오늘은 컴퓨터공학의 여러 주제 중 하나를 살펴볼 거예요. 무엇을 배워보고 싶나요?
>
> **플레이어 선택:** 자료구조 / 알고리즘 / 컴퓨터 과학 기초

플레이어가 **자료구조**를 선택한다.

> **교수:** 자료구조는 데이터를 정리하고 관리하는 방식이에요. 그중 스택은 나중에 넣은 자료를 먼저 꺼내는 구조죠.
>
> **친구:** 접시를 쌓으면 마지막에 올린 접시부터 꺼내는 것과 비슷하네요.
>
> **교수:** 맞아요. 그럼 스택이 어떻게 동작하는지 문제로 확인해 볼까요?

이후 AI가 생성할 수 있는 문제의 예시:

> 빈 스택에 `3`, `7`, `2`를 순서대로 넣은 뒤 두 번 꺼냈습니다. 두 번째로 꺼낸 값은 무엇인가요?
>
> ① 3　② 7　③ 2　④ 아무것도 없음
>
> **정답:** ② 7
> **풀이:** 마지막에 넣은 2가 먼저 나오고, 그다음 7이 나온다.

오답을 골라도 교수나 친구가 풀이를 설명해 학습이 이어지도록 한다.

### 물리학과 확장 예시

향후 물리학과에서 **역학**을 선택한 경우, 힘과 가속도에 관한 강의 대화 뒤 다음과 같은 계산 문제를 생성할 수 있다.

> 질량이 `2kg`인 물체에 `6N`의 합력이 작용합니다. 가속도는 얼마인가요?
>
> **정답:** `3m/s²`
> **풀이:** `a = F / m = 6 / 2 = 3m/s²`

이는 확장 예시이며, 1차 시범 범위는 컴퓨터공학 3개 루트다.

## 5. 대화와 AI 생성의 역할

**강의 대화의 뼈대는 사전에 작성한다.** 교수의 말투와 스토리 흐름을 유지하고, 퀴즈에서 어떤 개념을 물어볼지 분명히 하기 위해서다.

AI에는 다음 정보를 전달해 퀴즈를 생성한다.

- 학과와 교수
- 플레이어가 선택한 주제
- 방금 강의에서 설명한 개념과 학습 목표
- 전공자 또는 비전공자 난이도
- 문제 유형과 보기 개수
- 문제의 조건, 정답, 풀이를 함께 반환하라는 요구사항

교수의 짧은 정답·오답 반응에도 AI를 활용할 수 있지만, **핵심 수업 내용과 문제의 학습 범위는 사전에 정한 루트 정의를 따른다.**

## 6. 퀴즈 생성 및 검증 요구사항

1차 버전은 **4지선다 객관식, 정답 하나, 문제 1개**를 기본으로 한다.

생성 결과에는 최소한 다음 정보가 필요하다.

```json
{
  "topic": "자료구조",
  "concept": "스택의 후입선출",
  "question": "문제 본문",
  "choices": ["보기 1", "보기 2", "보기 3", "보기 4"],
  "answerIndex": 1,
  "explanation": "정답과 풀이"
}
```

`answerIndex`의 시작값이 0인지 1인지는 구현 시 프로젝트 규칙에 맞춰 명시한다.

생성된 문제는 화면에 표시하기 전에 다음을 확인한다.

- 선택한 주제와 강의에서 다룬 개념에 맞는가
- 보기 4개가 모두 있고 중복되지 않는가
- 정답 번호가 유효하고 정답이 하나인가
- 문제를 푸는 데 필요한 조건이 충분한가
- 풀이와 정답이 서로 일치하는가
- 계산이나 정해진 연산 결과는 검산할 수 있는가

형식 확인만으로 문제의 지식이 정확하다고 보장할 수는 없다. **스택 연산·숫자 변환·물리 계산처럼 답을 코드로 확인할 수 있는 유형부터** 우선 적용한다.

검증에 실패하거나 AI 요청이 실패·지연되면 해당 주제의 **미리 검토한 기본 문제**를 제공한다. 플레이어가 문제 오류 때문에 진행을 멈추지 않도록 한다.

## 7. 난이도

기존 전공자·비전공자 선택과 연결하는 방향으로 설계한다.

- **비전공자:** 강의에서 설명한 개념을 한 번 적용하는 문제. 필요한 조건과 예시를 충분히 제시한다.
- **전공자:** 같은 개념을 조금 더 긴 연산이나 새로운 상황에 적용하는 문제. 강의에서 다루지 않은 지식을 전제로 요구하지 않는다.

난이도 차이는 구현 전에 주제별 문제 예시를 작성해 검토한다.

## 8. 정답·오답 결과

정답을 맞히면 교수의 긍정적인 반응과 간단한 풀이를 보여준다. 오답을 골라도 정답과 풀이를 보여주며, 선택한 답이 왜 다른지 이해할 수 있게 한다.

기존 프로젝트의 점수·호감도·엔딩 수치에 이 결과를 어떻게 반영할지는 **미결정**이다. 구현 담당자는 현재 미니게임 결과 구조를 확인한 후 연결 방안을 제안한다. 1차 시범에서는 결과를 표시하고 기존 흐름으로 복귀하는 것부터 확인할 수 있다.

## 9. 1차 범위와 완료 기준

**범위**

- 컴퓨터공학 관련 교수 한 명
- 주제 3개: 자료구조·알고리즘·컴퓨터 과학 기초
- 주제별 강의 대화
- 선택한 주제와 강의 개념에 맞는 AI 객관식 문제 1개
- 정답·오답 풀이와 기존 흐름 복귀
- AI 실패 또는 검증 실패 시 주제별 기본 문제
- 기존 전공자·비전공자 설정에 맞춘 난이도

**완료 확인**

- 세 주제를 각각 골랐을 때 강의 대화가 해당 주제로 바뀐다.
- 문제의 개념이 선택한 주제와 강의 내용에 맞는다.
- 전공자·비전공자 설정이 문제 난이도에 반영된다.
- 정답과 오답 모두 풀이를 본 뒤 진행할 수 있다.
- AI 응답이 실패하거나 형식이 잘못돼도 기본 문제로 진행할 수 있다.
- 문제의 정답과 풀이를 반복 확인해 오류 사례를 기록한다.

## 10. 구현 담당 에이전트 확인 사항

- 현재 교수 선택 이후의 대화 분기와 퀴즈·미니게임 진입 구조
- 기존 AI 요청 방식, 응답 형식 검증, 시간 초과 및 대체 흐름
- 전공자·비전공자 난이도 값과 결과 처리 구조
- 주제 선택 상태를 대화부터 문제 생성까지 전달할 위치
- 문제 검산이 가능한 주제와 별도 검토가 필요한 주제
- AI 문제 생성 중 대기 화면과 실패 시 기본 문제 전환 방식

**핵심 요구사항:** 플레이어가 고른 주제에 맞는 강의 내용이 대화에 포함되고, 그 강의에서 다룬 전공 개념을 적용하는 AI 문제가 이어져야 한다.
