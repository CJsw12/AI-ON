# 수어 지문자 인식 미니게임 계획서 (v0.2)

작성: Claude, 2026-11-26 · 상태: **Codex 검토 반영(판정: 수정 후 진행)** · Antigravity 검토는 실행 환경 문제로 미실시

## 1. 목표와 범위

웹캠으로 플레이어의 손 모양을 인식해 **한국 수어 지문자 5개 내외**를 판정하는 미니게임을 만든다.
AI 활용 경진대회에서 "인터넷·유료 API 없이 PC 안에서 실시간으로 도는 AI"를 보여 주는 것이 목적이다.

| 포함 | 제외 |
|---|---|
| 한 손, 정지 자세 지문자 5개(최대 8개) | 움직임이 필요한 지문자, 두 손 지문자 |
| 글자별 인식과 "자세 유지" 판정 | 단어·문장 수어 인식, 번역 |
| 학습용 데이터 녹화 도구(손 관절 좌표만 저장) | 영상·사진 저장 |
| 로컬 추론(MediaPipe HandLandmarker + 작은 분류 모델) | 클라우드 API |

발표 문구 원칙: "수어 번역기"라고 하지 않는다. **"수어 지문자를 처음 배우는 사람을 위한 AI 체험"**으로 소개한다.

## 2. 이미 있는 것과 확인된 한계

- `Packages/com.github.homuler.mediapipe`: `Tasks/Vision/HandLandmarker` API와 `PackageResources/MediaPipe/hand_landmarker.bytes`가 있다.
  - **한계**: `MediaPipeAssetInstaller.cs`는 얼굴 모델만 `StreamingAssets`로 복사한다. 손 모델은 패키지 안에만 있어 **빌드에 포함된다는 보장이 없다.** `BaseOptions`는 파일 경로와 바이트 버퍼를 모두 받으므로, 복사 또는 바이트 로딩 중 하나를 P0.5에서 정하고 Windows 빌드로 확인한다.
- `com.unity.ai.inference` 2.6.1: UnitEye가 이미 `ModelLoader`·`Worker`로 ONNX를 쓴다(`GazeEstimationRunner.cs`). 작은 MLP 실행은 타당하나, 연산자 호환·임포트·CPU 백엔드·빌드 포함은 미검증이다.
- 웹캠: UnitEye 시선 추적과 `GameController.PlayerPhoto.cs`가 카메라를 쓴다.
  - **한계**: `StopWebcamTracking()`(`GameController.GazeTest.cs`)은 추적 객체를 파괴하고 **보정 상태까지 초기화**한다. "정지 후 자동 복원"은 지금 구조로 안 된다. 4.4절 참고.
- 미니게임: `MiniGameKind` 팩토리(`MiniGames.cs`)는 학과 스토리용이고, 하이라이트 탭(`GameController.GazeHighlight.cs`, `GameMenus.cs`)은 별도 진입 흐름이다. 둘이 자동으로 연결되지 않는다.
- 회귀 테스트: `Tests/*.ps1`이 Unity 의존이 없는 C# 파일을 .NET으로 컴파일해 검사한다.

## 3. 글자 선정 기준

최종 글자는 **국립국어원 한국수어사전의 지문자 영상으로 확인**하고, 가능하면 수어 전공자나 농인 1명에게 손 모양 검수를 받은 뒤 확정한다. 이 계획서는 글자를 미리 확정하지 않는다.

1. 한 손으로 하고 움직임 없이 멈춘 자세로 표현된다.
2. 손바닥이나 손등이 카메라를 향해 관절이 잘 보인다.
3. 후보끼리 손가락 펴짐 패턴이 뚜렷하게 다르다. 비슷한 쌍은 하나만 넣는다.
4. 자음 위주로 5개를 먼저 고르고, 결과가 좋으면 8개까지 늘린다.

## 4. 기술 구조

```
웹캠 프레임 ─▶ MediaPipe HandLandmarker (관절 21개 + 왼손/오른손 판정)
            ─▶ 손 미감지면 즉시 "손 없음" 상태 (분류기에 넣지 않음)
            ─▶ 특징 정규화 (순수 C#)
            ─▶ 분류기 (k-NN 또는 ONNX MLP) → 글자별 점수
            ─▶ 거절 규칙 (거리·마진) → "모름" 또는 글자
            ─▶ 시간 안정화 (타임스탬프 기반 창 투표)
            ─▶ 미니게임 판정 ("0.6초 유지 시 정답")
```

### 4.1 특징 정규화 (`SignFeatures.cs`, Unity 의존 없음)
- **좌표계 규약을 먼저 고정한다**: MediaPipe 정규화 좌표(x, y는 0~1)를 실제 픽셀 비율로 되돌린다(x × 프레임 폭, y × 프레임 높이). 그래야 해상도·종횡비가 바뀌어도 모양이 유지된다. z는 단위가 달라 처음에는 쓰지 않고, 필요하면 P2 결과를 보고 추가한다.
- 손목(0번)을 원점으로 옮기고, 손바닥 크기(손목 ↔ 가운뎃손가락 시작 관절 거리)로 나눈다. 크기가 최소값 미만이면 그 프레임은 "손 없음"으로 처리한다(0 나눗셈 방지).
- 왼손이면 x축을 뒤집어 오른손 기준으로 맞춘다. 카메라 좌우 반전 여부와 MediaPipe 왼손/오른손 판정의 기준을 함께 정의하고 테스트로 고정한다. 판정이 프레임마다 뒤바뀌는 경우를 대비해 최근 판정을 투표로 정한다.
- 손 회전(손목 기울기)은 정규화하지 않는다. 지문자는 손 방향 자체가 의미일 수 있기 때문이다. 녹화 시 기울기를 섞어 학습으로 흡수한다.
- 손가락 마디 굽힘 각도(손가락당 2~3개)를 추가한다.
- **학습과 실행의 전처리 일치**: 녹화 도구는 정규화 **전** 원본 좌표와 프레임 크기를 CSV로 저장한다. Python 학습 스크립트는 같은 규칙을 다시 구현하고, C#과 Python에 같은 입력 10개를 넣어 출력이 일치하는지 검사하는 테스트를 둔다.

### 4.2 분류기와 거절 규칙
- 1단계(기준선): 순수 C# k-NN. 학습 없이 녹화 데이터만으로 동작해 시험 제작 판단을 가장 빨리 한다. **k-NN 점수는 확률이 아니므로** 가장 가까운 이웃까지의 거리 상한과 1·2위 차이(마진)로 거절한다.
- 2단계(본편): 작은 MLP. Python으로 학습해 ONNX로 내보내고 Inference Engine으로 실행한다. 소프트맥스 값만 믿지 않고 마진 규칙을 같이 쓴다.
- **"그 외 손 모양" 클래스**: 손 펴기, 주먹, 다른 지문자, 글자 사이 전환 동작, 얼굴 가림 등 다양하게 모은다. 손이 아예 안 보이는 경우는 관절 데이터가 없으므로 이 클래스가 아니라 4.3의 "손 없음" 상태로 처리한다.
- 임계값(거리·마진·확률)은 검증셋으로만 정하고, 최종 평가셋으로는 조정하지 않는다.
- P3에서 MLP가 k-NN보다 낫지 않거나 성능 기준을 못 넘으면 **k-NN을 그대로 채택**한다.

### 4.3 시간 안정화 (`SignVote.cs`, Unity 의존 없음)
- 최근 0.33초(프레임 수가 아니라 타임스탬프 기준) 안의 결과로 투표한다. 과반 글자가 있고 거절되지 않았을 때만 "인식됨"이다.
- 동률이면 "모름"으로 본다. "손 없음"이 섞이면 창을 비운다.
- 프레임이 0.2초 이상 끊기면 창과 유지 타이머를 초기화한다.
- 같은 글자를 0.6초 연속 유지하면 정답 처리한다. 수치는 모두 설정값으로 두고 P2·P4에서 조정한다.

### 4.4 웹캠 공유와 복귀
현재 `StopWebcamTracking()`은 보정까지 지우므로, 다음 순서로 다룬다.
- 진입 전 상태를 기록한다: 시선 추적 사용 여부, 장치(웹캠/iPhone), 보정 완료 여부.
- 웹캠 시선 추적 중이면 "보정이 초기화된다"는 안내 후 정지한다. 장치 해제는 프레임 종료 뒤에 하고, 손 추적은 그다음에 연다.
- 정상 종료·실패·취소 모두 같은 복귀 경로를 탄다. 손 추적 장치를 해제하고, 진입 전에 웹캠 시선 추적을 쓰고 있었다면 **재보정 화면으로 안내**한다(자동 복원은 하지 않는다).
- iPhone 시선 추적은 웹캠을 쓰지 않으므로 그대로 둔다. 동시 실행 성능은 P4에서 실측한다.
- 플레이어 사진 촬영 경로(`PlayerPhoto`)와 동시에 카메라를 열지 않는다.
- 카메라가 없거나 권한이 거부되면 "카메라 없이 보기"(손 모양 그림만) 모드로 바꾸고 게임은 멈추지 않는다.

## 5. 게임 설계

- **진입**: 1차는 하이라이트 탭에 새 진입점을 직접 추가한다(기존 `MiniGameKind` 팩토리와 별개). 화면 전환, 카메라 생명주기(4.4), 끝난 뒤 돌아갈 화면을 명세에 적는다. 사회복지학과 스토리 연결은 2차로 결정한다.
- **진행**
  1. 교수가 오늘 배울 지문자를 소개한다(손 모양 그림 + 짧은 설명).
  2. 연습: 글자 하나씩 따라 한다. 화면에 내 손 관절 뼈대와 글자별 점수 막대가 실시간으로 보인다.
  3. 도전: 제시된 글자를 제한 시간 안에 차례로 만든다. 조합 문제는 P0에서 고른 글자로 실제 만들 수 있는 것만 낸다.
- **AI 시각화** (시연용 핵심): 관절 21개 점·선, 글자별 점수 막대, "유지 중" 원형 게이지, 처리 시간(ms).
- **도움말**: 1·2위 점수 차이만으로는 어느 손가락이 틀렸는지 알 수 없다. 기본은 "손 모양 그림을 다시 보고 천천히 따라 해 보세요" 같은 일반 안내를 쓴다. 글자별로 특정 관절 조건(예: 엄지 끝 위치)을 실제로 측정해 둔 경우에만 구체적인 안내를 보여 준다.
- **개인정보 안내**: 시작 화면에 "영상은 저장·전송되지 않고, 손 관절 위치만 이 PC 안에서 계산합니다"를 표시한다.

## 6. 데이터 수집

- 녹화 도구(에디터 전용 또는 숨김 메뉴): 글자를 고르고 키를 누르는 동안 원본 관절 좌표, 프레임 크기, 왼손/오른손 판정, 타임스탬프, 사람 ID, 세션 ID를 CSV로 저장한다. 영상은 저장하지 않는다.
- **연속 프레임은 독립 표본이 아니다.** 녹화 단위를 "한 번 손을 올렸다 내리기(시도)"로 세고, 글자당 사람별 **15회 이상 시도**(시도당 1~2초)를 목표로 한다. 시도 사이에 거리, 손 기울기, 양손을 바꾼다.
- 사람 최소 4명(학습 2~3명, 검증 1명, 최종 평가 1명). 조명 2종 이상. 세션을 다른 날에 한 번 더 녹화한다.
- "그 외 손 모양"은 4.2의 목록으로 글자 1개와 비슷한 양을 모은다.
- 저장 위치: `Tools/SignData/raw/`(Git 제외). 학습된 ONNX 모델만 `Assets/StreamingAssets/`에 커밋한다. 원본 좌표 커밋 여부는 팀 동의 후 결정한다.

| **P0.5 기술 확인** | 손 모델 로딩 방식 결정, 웹캠 → HandLandmarker → 관절 출력, Windows 빌드 | **빌드된 exe**에서 관절 21개가 그려지고, 시연 PC에서 평균·최대 프레임 시간 기록 | Codex 워커(코드) + 사용자(실행) |
| P1 기반 코드 | `SignFeatures`, `SignVote`, k-NN, 녹화 도구, C#·Python 전처리 일치 테스트 | 새 PS 단위 테스트와 기존 회귀 테스트 전부 exit 0, Unity 컴파일 오류 0 | Codex 워커 |

| P3 MLP·ONNX | 학습 스크립트, ONNX 내보내기, Inference Engine 실행 | 같은 검증셋에서 k-NN 이상. 시연 PC·CPU 백엔드에서 분류 1회 처리 시간 중앙값 5ms 이하(손 추적 제외). 미달이면 k-NN 채택 | Codex 워커 + 사용자 실측 |
| P4 미니게임 | 하이라이트 탭 진입, 시각화, 4.4 복귀 경로, 카메라 없음 대체 | 회귀 테스트 전부 exit 0, Unity 컴파일 오류 0, 실기에서 진입·정상 종료·취소·카메라 없음 4경로 확인 | Codex 워커 + 사용자 |
| P5 최종 평가·발표 | **봉인한 최종 평가 담당 1명**으로 한 번만 측정, 교수 대사, 시연 대본 | 측정표 기록, 시연 PC에서 3분 시연 통과 | 팀 |

**측정표 항목**: 글자별 재현율, 글자별 오인식(혼동표), "그 외 손 모양" 오인식률, 5초 안 성공률, 시도 수, 참여 인원.

**중단 기준 (잠정, 근거 있는 수치 아님)**: P2에서 글자별 재현율 평균이 60% 미만이면 지문자를 접고 숫자 손 모양(1~5)이나 가위바위보로 범위를 바꾼다. 60~80%면 혼동표에서 문제 쌍을 빼고 한 번 더 측정한다. 수치는 P2 첫 측정 후 팀이 다시 정한다.

## 8. 검증 방법

- 단위 테스트(`Tests/SignFingerspelling.Tests.ps1` 신규): 정규화(이동·크기·종횡비·좌우 반전 불변, 손바닥 크기 0 처리), 투표(과반·동률·손 없음·끊김 초기화), k-NN 거리·마진 거절, C#·Python 전처리 일치(고정 입력 대조값).
- 정확도: 사람 단위로 학습·검증·최종 평가를 나눈다. 임계값과 글자 선정은 검증 담당 데이터로만 정하고, 최종 평가 담당 데이터는 P5에서 한 번만 쓴다.
- 성능: 시연 PC에서 손 추적 + 분류 + 화면 그리기를 포함해 평균과 최대 프레임 시간을 기록한다.
- 기존 회귀 테스트와 Unity 컴파일 확인. PS 테스트 통과만으로 실기 동작을 보장하지 않으며, 실기 검증 전 항목은 "미검증"으로 적는다.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 손 모델이 빌드에 빠짐 | P0.5에서 빌드된 exe로 확인 |
| 손이 얼굴 앞·화면 가장자리에서 추적 끊김 | "손을 이 상자 안에" 가이드, 미감지 시 즉시 "손 없음" |
| 모르는 손 모양을 아무 글자로 인식 | 거리·마진 거절, "그 외 손 모양" 다양화, 오인식률을 통과 조건에 포함 |
| 왼손/오른손 판정 흔들림 | 판정 투표, 정규화 규약 테스트 |
| 같은 데이터로 반복 조정해 정확도가 부풀려짐 | 검증셋과 봉인한 최종 평가셋 분리 |
| 조명·배경에 따른 정확도 하락 | 녹화 시 조명 2종 이상, 시연장 사전 측정, 임계값 설정 메뉴 |
| 시선 추적 보정이 초기화됨 | 진입 전 안내, 종료 후 재보정 안내 |
| 시연 PC 성능 부족 | 처리 해상도 낮추기, 손 추적 빈도 조절. `hand_landmark_lite`는 Task 번들 대체 가능 여부가 미확인이라 P0.5에서 확인 |
| 수어 표현 오류로 인한 신뢰 문제 | 사전 영상 확인과 검수, 발표에서 범위를 정직하게 설명 |
