## ① 문제 정의 (20점, 50~400자)

진로를 정해야 하는 **고등학생과 대학 신입생**은 학과 이름과 교육과정 문서만 보고 전공을 고른다. 실제 수업 분위기, 교수와의 소통 방식, 전공 지식의 난이도를 입학 전에 직접 겪어 볼 방법이 없어, 입학 후에야 적성 불일치를 깨닫는다. 기존 학과 소개는 일방향 글·영상이라 "내가 이 전공에 맞는가"를 스스로 확인할 수 없다. 우리 팀은 이를 **비주얼 노벨 기반 전공 체험 게임**으로 해결한다. 플레이어는 16개 학과 32명의 교수 NPC와 대화하고, 전공 개념을 담은 19종 미니게임을 풀며, 선택에 따라 호감도와 성향이 바뀌어 8가지 엔딩으로 갈린다. 생성형 AI가 자유 답변에 실시간으로 반응할 수 있게 된 지금, 정해진 선택지를 넘어선 **대화형 전공 탐색**이 가능해졌다.

## ② AI 활용 (25점, 100~600자)

1) **아트**: 이미지 생성 AI로 교수 초상을 단색 배경으로 생성해 배경 제거를 자동화하고, 같은 인물의 기본·기쁨·찡그림 **표정 세트**를 양산했다(초상 112장). 얼굴 위치 정규화 표는 스크립트로 자동 생성한다.
2) **대화**: **OpenAI API**(GPT-6.1 Terra)를 Cloudflare Worker 릴레이로 호출하고, 키는 서버 비밀값으로만 둔다. **프롬프트 엔지니어링**으로 교수 페르소나, 호감도 5단계 말투, 최근 장면 맥락, 기획된 선택지·점수(채점 기준)를 주입한다. 모델은 태도·응답·성의 등 6개 항목만 판정하고 점수는 코드 규칙이 계산해, 실험 108건 중 107건이 의도대로 채점됐다(중간값 2.7초).
3) **음성**: 교수 본인 녹음 약 3분으로 **음성 복제 TTS**(CosyVoice3) 모델을 만들어 대사 72줄을 생성하고, Whisper 받아쓰기로 검수했다(글자 오류 약 3%).
4) **시선 추적**: MediaPipe 얼굴·홍채 인식으로 웹캠 시선을 추정해, 교수 얼굴을 바라본 횟수를 엔딩 통계에 기록한다.

### 멘토링 반영 사례: 네트워크 오류 대비 Fallback 다이얼로그

- **피드백**: 외부 AI API가 지연되거나 끊기면 대화가 멈춰 게임 진행이 막힐 수 있다.
- **반영 결과**:
  1. **결정론적 Fallback 다이얼로그**: 모든 AI 대화 지점에 기획자가 미리 작성한 선택지·점수·교수 반응이 있다. 응답이 늦거나 실패하면 `선택지로 전환` 버튼 한 번으로 이 오프라인 선택지로 진행한다.
  2. **이중 모델 전환**: 서버는 GPT-6.1 Terra를 12초 안에 받지 못하거나 오류·빈 응답이면 Gemini로 자동 전환한다. 인증·한도 오류(401/403/429)가 나면 10분간 Terra를 건너뛰고, 하루 호출 수 상한(500회)으로 비용을 막는다.
  3. **오류 분류 안내**: 클라이언트는 40초 타임아웃을 두고, 504(시간 초과)·502/503(일시 장애)·네트워크 단절을 구분해 "오프라인 선택지로 전환" 안내를 띄운다.
  4. **잘못된 응답 차단**: 판정 항목이 허용된 값과 정확히 일치하지 않으면 형식 오류로 보고 점수를 반영하지 않는다. 힌트 요청이 실패하면 차감한 질문 기회를 돌려준다.
