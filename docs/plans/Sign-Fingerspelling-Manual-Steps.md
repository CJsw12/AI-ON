## 역할과 시작 대사

| 역할 | 하는 일 | 말할 예 |
|---|---|---|
| 진행자 | 시간·동의·휴식 관리 | “언제든 중단하거나 철회할 수 있어요.” |
| 녹화 조작자 | Unity 창과 저장 상태 확인 | “지금 시작합니다. 손을 올려 주세요.” |

| 검수자 | 사전 영상과 후보 표현 확인 | “이 손 모양과 방향을 다시 비교합시다.” |

> **데이터 보안**: 현재 녹화기는 영상·이미지를 저장하지 않고 관절 CSV만 저장한다. 원본과 게임 폴더의 CSV, 측정 보고서를 Git이나 Claude 등 AI 서비스에 올리지 않는다. 모임 끝에 담당자가 접근 제한된 승인 저장소와 암호화된 별도 매체에 백업하고 위치·보관자·종료일을 아래에 적는다. 가명과 실명 대응표는 오프라인 종이로만 보관한다.

## 1. 1회차: 글자 5개 확정

준비물: 인터넷, 국립국어원 한국수어사전, 검수자, 기록지. 예상 30~45분. 기록: [원 계획 3절](Sign-Fingerspelling-Plan.md)의 팀 결정과 아래 기록표.

1. 검색창에서 `국립국어원 한국수어사전`을 찾아 공식 사이트에 들어가 지문자 영상을 찾는다. 정확한 사이트 내 메뉴는 **미확인**이다.
2. 한 손 정지 자세, 손바닥 또는 손등이 카메라를 향하고 손가락 펴짐이 뚜렷하게 다른 자음 위주 5개를 고른다. 비슷한 쌍은 하나만 고른다.
3. 검수자에게 영상 링크와 손 방향·후보를 함께 보여 주고 정확성 및 참고 이미지 사용 가능 여부를 확인한다. 미응답이면 미검수로 기록한다.
4. 정상: 후보 5개, 사전 링크, 확인자와 날짜가 기록된다. 찾기 어렵거나 의견이 다르면 확정하지 말고 보류한다.

## 2. 웹캠 실기 확인 (P0.5)

준비물: 동의된 CSV, 웹캠, 개발 PC와 Windows 빌드. 15~25분. 결과: 아래 실기 및 성능 표. 개발 PC와 학교 PC 각각 확인한다.

0. **처음엔 학습 데이터가 없어 게임 화면이 `학습 데이터 없음`만 띄우고 카메라를 켜지 않는다.** 조작자가 본인 손으로 임시 데이터를 만든다(약 10분).
   - 4절 방법으로 가명 `test`, 세션 `s1`, 글자 목록 `주먹,보자기,검지,_other`를 입력하고 글자마다 3회씩 녹화한다.
   - `Tools/SignData/raw/test/s1.csv`를 `Assets/StreamingAssets/SignData/`로 복사한다.
   - 확인이 끝나면 복사본을 지운다. 이 임시 데이터는 측정에 쓰지 않는다.
1. Unity Play 또는 빌드 실행 → `미니게임` → `하이라이트` → `수어 지문자`.
2. `디버그 보기`를 켠다. 관절 점·선이 손 위에 맞는지, 좌우로 움직일 때 영상과 겹치는지 본다. 가까이·멀리, 밝은 조명·다른 조명에서 확인한다.
3. 빈 화면과 얼굴만 있는 화면에서 글자가 정답 처리되지 않는지 확인한다. 얼굴을 녹화하지 않는다.
4. 화면의 `감지 평균/중앙값/95%/최대`, `갱신 ... 회/초`를 기록한다. 이는 손 감지 시간이며 전체 프레임 시간과 다르다. Windows exe에서 동일하게 반복한다.
5. 안 보이면 카메라 권한과 다른 앱의 점유, 손 모델 파일, 학습 CSV를 확인한다. 실제 좌우 판정의 거울 기준과 Windows 빌드 결과는 실기 전 **미확인**이다.

## 3. 동의와 보관

준비물: 아래 동의서, 필기구, 봉투. 참여자당 5분. 기록: 서명된 종이는 지정 담당자가 별도 보관하고 가명만 세션 기록지에 쓴다.

1. 목적, 관절 좌표, 현재 이미지를 저장하지 않는 점, 접근자, 종료일과 철회 연락처를 설명한다. 각 항목을 따로 선택받는다. 미동의 항목은 진행하지 않는다.
2. `p01` 같은 실명과 무관한 가명을 부여한다. 대응표는 오프라인 종이에만 두고 CSV나 AI 서비스에 넣지 않는다.
3. 철회 요청 시 담당자는 원본·백업·캐시·체크포인트·클라우드 사본을 삭제하고 해당 데이터로 만든 모델을 폐기해 재학습한다. 배포 모델도 다음 빌드에서 교체한다. 삭제 완료를 기록한다.
4. 보관 종료일에 이미지 원본을 삭제한다. 좌표의 보관 기간은 팀이 정한다. 학교 PC의 이미지 원본·캐시·중간 산출물도 학습 후 삭제한다. 이 녹화기는 이미지 수집을 지원하지 않는다.

## 4. 녹화 세션 대본

준비물: 동의, 조용한 장소, 웹캠, Unity, 아래 기록지. 사람당 약 20~30분이며 실제 시간을 기록한다. 조작자는 Play → `Tools → Sign → Recorder`를 연다.

| 시간 | 진행자와 조작자 | 참여자 |
|---|---|---|
| 0~3분 | 동의 확인, `사람 ID (가명)`, `세션 ID`, `글자 목록 (쉼표 구분)` 입력. 예 `A,B,C,D,E,_other` | 카메라와 편한 위치 확인 |
| 3~5분 | `손 추적 시작` 클릭, `손 감지 여부`가 `감지됨`인지 확인 | 손을 올려 관절 점 확인 |
| 5~15분 | 글자 하나씩 선택해 시도. “시작, 유지, 끝” 신호 | 손 올리기 → 유지 → 내리기. 중간에 거리·기울기·손을 바꾼다 |
| 15~17분 | 휴식과 횟수 확인 | 편히 쉰다 |
| 17~25분 | 남은 글자와 `_other` 녹화 | 다른 지문자·전환·얼굴 가림 등 선정 글자가 아닌 다양한 모양 |
| 25~30분 | 저장·누락 확인, `손 추적 종료`, 기록지 작성 | 다음 날 세션과 조명 변경 확인 |

1. 글자 선택 후 창에 포커스하고 텍스트 입력을 끝낸다. Space를 누르고 있는 동안 녹화하고 놓으면 종료한다. 또는 `시도 녹화 시작 (또는 창 포커스 중 Space 유지)`을 누르고 `시도 녹화 종료`를 누른다. 포커스를 잃으면 Space 녹화가 종료된다.
2. 한 시도는 손을 한 번 올리고 유지하고 내리는 것이다. 각 글자와 `_other`를 시도한다. 5글자 × 15회는 75회이고 `_other`는 별도다. 다른 날의 세션과 합쳐 사람·글자별 15회 이상을 확보한다. 조명도 2종 이상 쓴다.
3. `글자별 시도 수 (목표 15회)`는 현재 사람·세션 파일 기준이므로 다른 날의 수는 합산한다. `시도 저장 완료`와 프레임 수를 확인한다. `너무 짧음: 유효 프레임` 경고는 유효 10프레임 미만이므로 다시 녹화한다.
4. 저장 실패 시 창을 닫지 말고 `다시 저장`을 누른다. `보관 시도 버리기`는 미저장 시도를 폐기한다. 정상 파일은 `Tools/SignData/raw/<가명>/<세션>.csv`다.

## 5. 파일 정리와 백업

준비물: 동의 범위, 승인 저장소. 10분. 기록: 담당자·경로·날짜를 결정표에 적는다.

1. 원본 `Tools/SignData/raw/` 아래 가명·세션 파일을 확인한다. 봉인 평가자는 모델 선택이나 게임 학습에 넣지 않는다.
2. 동의 범위에 맞는 학습용 CSV만 `Assets/StreamingAssets/SignData/`에 복사한다. 하위 폴더도 읽힌다. 정상: 게임에 글자와 점수 막대가 나온다. 데이터가 없으면 `학습 데이터 없음`이 나온다.
3. 원본, 보고서, 게임 폴더 CSV와 `.csv.meta`는 Git에서 무시한다. README와 그 메타는 유지된다. 팀이 좌표 커밋을 결정하면 `.gitignore` 해당 규칙을 팀 합의로 수정하고 동의 범위를 재확인한다.
4. 승인된 암호화 저장소에 백업한다. 보관자·위치·종료일을 적고 접근과 복구를 확인한다. 파일이 안 보이면 Recorder의 `저장 경로`와 가명·세션을 확인한다.

## 6. 교차 검증과 최종 평가

준비물: 최소 5명(봉인 1명 포함)의 동의된 녹화, PowerShell 5.1. 10~30분 이상. 결과는 `Tools/SignData/reports/`와 결정표에 기록한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Measure-SignKnn.ps1 -Folder Tools/SignData/raw -Sealed p05 -Seed 1701 -K 5
# 모델과 설정을 모두 고른 뒤에만 한 번 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Measure-SignKnn.ps1 -Folder Tools/SignData/raw -Sealed p05 -Seed 1701 -K 5 -Final
```

1. `p05`를 봉인 가명으로 바꾸고 첫 명령을 실행한다. 교차 검증에서 봉인자를 제외한다. 봉인 제외 2명 미만이면 오류다. 계획의 목표 인원은 최소 5명이다.
2. 글자별 재현율 80% 이상, 그 외·손 없음 포함 오인식률 10% 이하, 5초 성공률 90% 이상이 잠정 기준이다. 현재 손 없음은 CSV에 없어 **미측정**, 5초 성공은 근사치다. 합격을 단정하지 말고 실기 점검을 함께 기록한다.
3. 평균 재현율 60% 미만이면 숫자 손 모양이나 가위바위보로 범위 축소를 검토한다. 60~80%면 혼동이 큰 쌍을 빼고 다시 측정한다. 결과는 작은 탐색 실험이다.
4. 최종 평가는 모델 선택 후 봉인 평가자로 한 번만 한다. 도구는 반복을 자동 차단하지 않으므로 기록자가 실행 여부를 기록한다. 봉인 1명의 결과는 일반화를 보장하지 않는다.

## 8. 학교 PC 성능

준비물: 승인된 Windows 빌드 폴더 전체와 데이터 반입 허가, 웹캠. 20~30분. 보안 정책을 우회하지 않는다. 빌드 폴더 전체를 승인된 매체로 옮겨 exe를 실행한다. 경로와 exe 이름은 빌드마다 다르므로 **미확인**이다.

1. 2절 화면에서 워밍업하고 `디버그 보기`의 감지 평균·중앙값·95%, 갱신률을 기록한다. 갱신 목표는 20회/초 이상이다.
2. 전체 프레임 시간 평균·중앙값은 Unity 로그 `[Hand probe]`의 `프레임 ms 평균`, `중앙값`에서 확인한다. Windows 플레이어 로그의 실제 위치는 **미확인**이다. 전체 프레임 시간 95백분위는 현재 화면·해당 로그에 표시되지 않아 **미확인**이며 별도 측정이 필요하다.
3. 측정 불가면 빈칸을 0으로 채우지 않고 미측정 사유를 적는다. 정책이나 권한 문제면 담당자에게 문의한다.
