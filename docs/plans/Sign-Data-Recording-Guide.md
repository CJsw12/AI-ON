# 수어 지문자 학습 데이터 녹화 가이드 (팀원 개인용 · 에이전트 보조용)

작성 2026-11-27 · sh-com-claude

- 같은 내용의 PDF: `docs/reports/AI-ON-수어데이터-녹화가이드.pdf` (이 문서를 고치면 PDF도 다시 만든다)
- 짝 문서: 계획·학습·진행 대본 전체는 [Sign-Fingerspelling.md](Sign-Fingerspelling.md)

**이 문서의 목적:** 팀원 **한 사람(개인)** 이 혼자서 학습 데이터를 만들 수 있게 하고, 옆에서 돕는 에이전트(AI)도 같은 기준으로 안내·점검할 수 있게 한다.

**누가 무엇을 읽나**

| 읽는 사람 | 읽을 부분 |
|---|---|
| 녹화할 팀원 | 0~8절, 10~11절 |
| 팀원을 돕는 에이전트 | **9절을 먼저**, 그다음 나머지 |
| 학습 PC 담당(사람·에이전트) | 7~9절 + [Sign-Fingerspelling.md](Sign-Fingerspelling.md) 2부·4부 |

---

## 0. 한눈에 보기

> **한 줄 요약:** 팀이 정한 한 손 지문자 5개를 사람마다 글자당 15번 이상, 그 밖의 손 모양(`_other`)을 15번 이상 찍는다. 찍는 방법은 Unity 녹화 도구에서 Space를 누르고 있는 것뿐이다. 영상은 저장되지 않고 **손 관절 좌표 CSV**만 남는다.

| 항목 | 값 |
|---|---|
| 어떤 동작 | 팀이 확정한 **한 손 정지 지문자 5개** + `_other`(그 밖의 모든 손 모양) |
| 얼마나 | 글자별 **15회 이상**, `_other` **15회 이상**(권장 30회) → 한 사람 **최소 90회** |
| 몇 세션 | **2세션**(다른 날, 다른 조명). 세션 하나에 **20~30분** |
| 시도 한 번 | 손을 올림 → **1~2초 유지** → 내림 (Space를 누르고 있는 동안 녹화) |
| 남는 것 | `Tools/SignData/raw/<가명>/<세션>.csv` (관절 좌표 21점 × 프레임) |
| 팀 전체 | 최소 **5명**(그중 1명은 봉인 평가자) |
| 점검 | 녹화 후 `Check-SignRecording.ps1`로 확인(7절). 좌표는 출력하지 않는다 |
| 하지 말 것 | Git·AI 서비스·메신저·공용 드라이브에 CSV 올리기 |

**5단계 순서:** ① 동의와 가명 → ② 준비 → ③ 녹화(2세션) → ④ 점검 → ⑤ 전달과 보관

**자주 하는 오해 한 가지:** "에이전트에게 데이터를 줘야 에이전트가 학습된다"가 **아니다.** CSV는 학습 PC에서 **작은 분류 모델**을 만드는 재료다. 에이전트는 그 학습 스크립트를 실행하고 **요약 숫자만** 본다. 에이전트나 채팅에 CSV를 붙여 넣지 않는다(9절).

## 1. 이 데이터가 어디에 쓰이나 (왜 이렇게 찍나)

- 게임은 웹캠으로 사용자의 손을 보고, MediaPipe가 **손 관절 21개 좌표**를 뽑아 준다. 거기서 특징 57개를 계산해 "어느 글자인지" 맞힌다.
- 학습 데이터 = 그 좌표를 **글자 이름표와 함께** 모은 것이다. 사람이 손 모양을 만들고, 도구가 프레임마다 좌표를 저장한다.
- **한 번의 시도**는 손을 한 번 올렸다 내리는 것이다. 평가도 프레임이 아니라 시도 단위로 한다.
- **사람마다 손 크기·습관이 다르므로** 평가는 "사람 단위"로 한다. 그래서 **여러 사람**이 찍는 것이 중요하고, 같은 사람이 많이 찍는 것보다 낫다.
- `_other`는 "선정 글자가 아닌 모든 손"을 가르치는 이름표다. 이것이 부족하면 **아무 손이나 정답 처리**된다.
- 좌우 규칙: 왼손은 관절 x를 뒤집어 오른손 기준으로 맞춘다. 다만 이 거울 기준은 실기 전 **미확인**이므로 **한 사람은 한 손으로 통일**한다.

## 2. 어떤 동작을 찍나

### 2.1 글자 5개 (팀 확정 사항)

글자는 팀이 모임 1회차에서 **국립국어원 한국수어사전의 지문자 영상**으로 확정한다(Sign-Fingerspelling.md 3부 1절). 아직 확정 전이면 **임의로 정해 찍지 않는다.** 확정되면 아래 표에 적는다.

| 번호 | 글자 | 사전 영상 링크 | 확인자·날짜 |
|---|---|---|---|
| 1 | ____ | ____ | ____ |
| 2 | ____ | ____ | ____ |
| 3 | ____ | ____ | ____ |
| 4 | ____ | ____ | ____ |
| 5 | ____ | ____ | ____ |

**선정 기준(요약):** 한 손, 움직임 없는 정지 자세, 손바닥 또는 손등이 카메라를 향함, 후보끼리 손가락 펴짐이 뚜렷이 다름(비슷한 쌍은 하나만), 자음 위주.

**녹화 도구에 입력하는 글자 이름**은 팀이 정한 이름 그대로 쓰고, **쉼표·따옴표·공백은 쓸 수 없다.** 한 번 정한 이름은 모든 사람이 똑같이 쓴다(`ㄱ`과 `기역`을 섞지 않는다).

### 2.2 `_other` — 선정 글자가 아닌 모든 것

다음을 골고루 섞어 **15회 이상**(권장 30회) 찍는다. 선정 글자와 비슷한 모양은 피한다.

| 종류 | 예 |
|---|---|
| 기본 손 모양 | 손 펴기(보자기), 주먹, 손가락 하나 들기 |
| 다른 지문자 | 선정하지 않은 지문자 |
| 움직임 | 손 흔들기, 글자와 글자 사이 **전환 동작**, 손을 반쯤 올린 중간 자세 |
| 흔한 방해 | 손으로 얼굴·머리 만지기, 손으로 입 가리기, 물건 집기 |

### 2.3 한 손으로 통일

평소 쓰는 손 **하나**로 모든 글자·`_other`를 찍는다. 세션이 바뀌어도 같은 손이다. 점검 도구가 한 사람 안에서 왼손·오른손이 섞이면 경고한다.

## 3. 얼마나 찍나

| 항목 | 기준 | 근거 |
|---|---|---|
| 글자별 시도 | 사람당 **15회 이상** | 계획서 6.3절 |
| `_other` 시도 | **15회 이상**, 권장 **30회**(다양하게) | 15회는 문서 기준, 30회는 제안 |
| 총 시도 | **최소 90회**(5글자 × 15 + 15), 권장 105회 이상 | 위 합 |
| 유효 시도 | 유효 프레임 **10개 이상**인 시도만 센다 | 녹화 도구 규칙 |
| 세션 | **2세션 이상**, 다른 날·다른 조명 | 계획서 6.3절, 3부 4절 |
| 인원 | 팀 전체 **5명 이상**, 1명은 봉인 평가자 | 계획서 6.3절 |
| 시간 | 세션당 **20~30분**(실제 시간을 기록) | 3부 4절 |

**두 세션에 나누는 제안(문서 기준은 합쳐서 15회):**

| | 세션 1 (첫날, 밝은 조명) | 세션 2 (다른 날, 다른 조명) | 합계 |
|---|---|---|---|
| 글자 하나당 | 8회 | 7회 | 15회 |
| `_other` | 15회 | 15회 | 30회 |

**시도마다 조금씩 바꾼다.** 같은 자세만 반복하면 쓸모가 줄어든다.

| 바꿀 것 | 방법 |
|---|---|
| 거리 | 가까이 / 보통 / 멀리를 번갈아(5회마다 바꾸기) |
| 위치 | 화면 가운데, 좌, 우, 위, 아래 |
| 기울기 | 손목을 조금씩 좌우·앞뒤로 |
| 손 크기 느낌 | 손을 약간 펴거나 모으기(글자 모양은 유지) |

> 화면의 `글자별 시도 수 (목표 15회)`는 **지금 열린 사람·세션 파일** 기준이다. 둘째 날 세션의 수는 합산되지 않으므로, 합계는 7절 점검 도구로 확인한다.

## 5. 동의와 가명

1. **동의가 먼저다.** 진행자가 목적, 저장 항목(관절 좌표), 영상·이미지를 저장하지 않는 점, 접근자, 보관 종료일, 철회 연락처를 설명하고 항목별로 선택을 받는다. 미동의 항목은 진행하지 않는다. 서식은 Sign-Fingerspelling.md 3부 3절.
2. **가명을 받는다.** 진행자가 `p01`처럼 실명과 무관한 이름을 준다. **실명과 가명의 대응표는 종이로만 보관**하고 CSV·채팅·AI에 쓰지 않는다.
3. **철회는 언제든 된다.** 철회하면 담당자가 원본·백업·사본을 지우고 그 데이터로 만든 모델을 폐기한다.
4. 가명과 세션 이름의 규칙: **공백·쉼표·따옴표·경로 문자(`\ / : * ? " < > |`)가 없어야 한다.** 예 `p01`, `s1`, `s2`.

## 6. 녹화 (Unity 녹화 도구)

화면 문구는 코드(`SignRecorderWindow.cs`)에서 옮겼다. 실제 Unity 화면에서의 실기 확인은 아직 하지 않았다(12절).

### 6.1 시작

1. Unity에서 프로젝트를 열고 **Play**를 누른다. (Play가 아니면 "Play 모드에서만 동작합니다"가 뜬다.)
2. 메뉴 **`Tools → Sign → Recorder`** 를 연다.
3. 입력한다.

   | 칸 | 넣을 값 | 예 |
   |---|---|---|
   | `사람 ID (가명)` | 받은 가명 | `p01` |
   | `세션 ID` | 세션 이름 | `s1` (둘째 날은 `s2`) |
   | `글자 목록 (쉼표 구분)` | 확정 글자 5개와 `_other` | `A,B,C,D,E,_other` (실제 글자로) |

   창 아래에 `저장 경로: …/Tools/SignData/raw/<가명>/<세션>.csv`가 보이면 입력이 맞다. 빨간 오류가 뜨면 칸의 규칙(공백·쉼표 금지)을 확인한다.
4. **`손 추적 시작`** 을 누르고 손을 올려 `손 감지 여부`가 **`감지됨`** 인지 본다. `미감지`면 조명·손 위치·카메라 가림을 확인한다.

### 6.2 시도 한 번 찍기

1. 글자 버튼에서 **찍을 글자를 고른다**(`▶`가 붙는다). `선택 글자`와 `시도 번호`를 확인한다.
2. 그 글자의 **손 모양을 만든다.**
3. 녹화 창을 한 번 **클릭해 포커스**를 준다(글자 입력칸이 편집 중이면 끝낸다).
4. **Space를 누르고 있는다.** 상태가 `녹화 중 [Space]`가 된다. **1~2초** 손 모양을 유지한다.
5. **Space를 뗀다.** `시도 저장 완료`와 프레임 수가 나온다. 손을 내린다.
6. 다음 시도에서는 **거리·위치·기울기를 조금 바꾼다.** 글자마다 목표 횟수까지 반복한다. 진행 막대가 `목표 달성`이 되면 그 파일 기준으로 15회가 찬 것이다.

> Space 대신 버튼 `시도 녹화 시작 (또는 창 포커스 중 Space 유지)`과 `시도 녹화 종료`를 눌러도 된다. **창이 포커스를 잃으면 Space 녹화는 끝난다.**

### 6.3 순서(세션 20~30분)

| 시간 | 할 일 |
|---|---|
| 0~5분 | 동의 확인, 입력, `손 추적 시작`, 감지 확인 |
| 5~15분 | 글자 1~5를 한 글자씩(합쳐서 목표의 절반 안팎) |
| 15~17분 | 휴식, 횟수 확인 |
| 17~25분 | 남은 글자와 **`_other`** (다양하게) |
| 25~30분 | `손 추적 종료`, 7절 점검, 기록지 작성 |

### 6.4 틀렸을 때

| 상황 | 방법 |
|---|---|
| 방금 시도가 틀림 | **`마지막 시도 삭제`** |
| 경고 `너무 짧음: 유효 프레임` | 유효 프레임 10개 미만. 손을 더 오래 유지해 **다시 찍는다** |
| `CSV 저장 실패(메모리 유지됨, 다시 저장 가능)` | 창을 닫지 말고 **`다시 저장`**. 안 되면 `보관 시도 버리기` |
| 글자를 잘못 골라 찍음 | 바로 `마지막 시도 삭제` 후 올바른 글자로 다시 |
| 중간에 끊김 | 같은 가명·세션으로 다시 열면 같은 파일에 **이어서** 저장된다 |

### 6.5 문제 해결

| 화면 문구·상황 | 조치 |
|---|---|
| `Play 모드에서만 동작합니다…` | Unity의 Play를 누른다 |
| `게임의 손 추적 화면이 이미 웹캠을 사용 중입니다…` | 게임의 손 추적 화면과 다른 카메라 앱을 닫는다 |
| `게임의 시선 추적이 웹캠을 사용 중입니다…` | 시선 추적을 중지한다 |
| `연결된 웹캠을 찾을 수 없습니다.` | 연결·권한을 확인한다 |
| `손이 보이지 않습니다` / `미감지` | 손 위치, 조명, 카메라 가림을 확인한다 |
| CSV가 어디 있는지 모름 | 창의 `저장 경로`를 본다 |

마지막에 **`손 추적 종료`** 를 눌러 카메라를 놓아 준다.

## 7. 점검 — 내 데이터가 쓸 만한가

녹화가 끝나면 **프로젝트 루트의 PowerShell**에서 실행한다. 이 도구는 **좌표를 출력하지 않고** 개수와 판정만 보여 준다(사람과 에이전트가 같이 써도 안전하다).

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Check-SignRecording.ps1 -Person p01 -Labels "A,B,C,D,E,_other"
```

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `-Folder` | 녹화 폴더 | `Tools/SignData/raw` |
| `-Person` | 이 가명만 점검(비우면 전원) | 전원 |
| `-Labels` | 확정 글자 목록(쉼표). 누락·오타를 찾는다 | 없음 |
| `-Target` | 글자별 목표 유효 시도 수 | 15 |
| `-MinFrames` | 유효 시도로 세는 최소 프레임 수 | 10 |

**정상 예(두 세션 합계):**

```text
== p01  (세션 2개: s1, s2)
글자             유효 시도     짧은 시도       프레임  판정
A                 15         0       330  OK
B                 15         0       330  OK
C                 16         0       352  OK
D                 15         0       330  OK
E                 15         0       330  OK
_other            16         0       352  OK

결과: 형식 정상, 모든 글자가 목표(15 회) 이상입니다.
```

**부족 예(글자 C가 모자라고 `_other`가 없고 세션이 1개):**

```text
== p02  (세션 1개: s1)
글자             유효 시도     짧은 시도       프레임  판정
A                 15         0       330  OK
...
C                 11         0       242  부족 (4회 더)
예상 글자 _other 의 녹화가 없습니다.

[주의]
  - p02: 세션이 1개뿐입니다. 다른 날·다른 조명의 세션을 한 번 더 녹화하세요(권장).
[목표 미달]
  - p02 / C : 유효 시도 11 / 15
  - p02 / _other : 녹화 없음
```

(위 예시는 합성 데이터로 실제 실행한 출력이다. 실제 참여자 데이터가 아니다.)

**종료 코드**

| 코드 | 뜻 | 다음 행동 |
|---|---|---|
| 0 | 형식 정상 + 목표 충족 | 8절로 |
| 2 | 형식은 정상, **횟수·글자가 모자람** | `부족`으로 표시된 글자를 더 녹화(같은 가명, 새 세션 또는 같은 세션) |
| 1 | **파일 형식 오류** | 오류에 적힌 파일·줄을 확인. 대개 가명·세션 이름이 CSV 안과 달라서 생긴다(9.4절) |

도구는 형식(헤더, 열 개수, 숫자, 손 구분, 가명·세션 일치)과 횟수를 검사한다. **손 모양이 맞는지, 조명이 다양했는지, 다른 날이었는지는 판단하지 못한다**(사람이 확인).

## 9. 에이전트(AI) 보조 가이드

> **에이전트가 먼저 지킬 것:** 참여자 데이터는 개인정보다. CSV 내용을 **읽지도, 출력하지도, 요약해 옮기지도 않는다.** 데이터 확인은 **`Check-SignRecording.ps1`의 출력만** 본다.

### 9.1 에이전트가 해도 되는 일 / 하면 안 되는 일

| 해도 되는 일 | 하면 안 되는 일 |
|---|---|
| 이 문서의 절차를 질문 순서대로 안내 | CSV 파일 열기·`cat`·`Read`·`head`·`Get-Content`로 내용 보기 |
| `Check-SignRecording.ps1` 실행과 **출력 해석** | CSV·좌표를 채팅·로그·보고서에 붙여 넣기 |
| 종료 코드별 다음 행동 안내(7절) | `git add`/`commit`/`push`로 데이터 올리기(`Tools/SignData/raw/`, `*.csv`) |
| 가명·세션 이름 규칙 확인, 입력 오류 설명 | 실명 또는 가명-실명 대응을 묻거나 기록하기 |
| Unity 녹화 도구의 화면 문구·오류 안내(6절) | **동의 여부를 대신 판단하기** — 사람이 확인 |
| 폴더 구조·경로 확인(`Get-ChildItem`으로 **파일 이름만** 보기) | 데이터를 외부(클라우드·다른 AI 서비스)로 보내기 |
| 학습 PC에서 학습·측정 스크립트 실행, **요약 숫자만** 보고 | 점검 실패 시 데이터를 직접 고쳐 쓰기(파일은 팀원이 다시 녹화) |

### 9.2 팀원이 "녹화 도와줘"라고 하면 — 진행 순서

에이전트는 아래 순서로 **하나씩 묻고 확인**한다.

| 순서 | 에이전트가 묻거나 하는 일 | 막히면 |
|---|---|---|
| 1 | "동의서에 서명하고 가명을 받았나요?" (**예**일 때만 계속. 가명 값만 받는다) | 진행자에게 문의하도록 안내 |
| 2 | "글자 5개가 팀 모임에서 확정됐나요? 표(2.1절)에 적힌 글자를 알려 주세요." | 확정 전이면 **중단**, 임의 글자 금지 |
| 3 | "이번 세션 이름(`s1`/`s2`)과 쓰는 손을 정했나요?" | 이전 세션과 **같은 손**인지 확인 |
| 4 | 6.1~6.2절 순서로 Unity 입력을 같이 확인(화면 문구를 말해 달라고 요청) | 6.5절 표 |
| 5 | 녹화가 끝나면 **7절 점검 명령**을 실행해 출력을 해석 | 종료 코드 표 |
| 6 | 부족한 글자·`_other`를 알려 주고 어떻게 더 찍을지 안내(3절 변주표) | — |
| 7 | 통과하면 8절 전달·보관과 기록지 작성 안내 | — |

에이전트가 실행할 명령(프로젝트 루트):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Check-SignRecording.ps1 -Person <가명> -Labels "<확정 글자 쉼표 구분>,_other"
```

### 9.3 출력 해석 표

| 출력 | 의미 | 에이전트의 안내 |
|---|---|---|
| `OK` | 그 글자는 유효 시도 15회 이상 | 다음 글자로 |
| `부족 (N회 더)` | N회 모자람 | 그 글자만 N회 더. 거리·위치를 바꿔서 |
| `짧은 시도 N개` | 유효 프레임 10 미만이라 세지 않음 | 손을 1~2초 유지해 다시 |
| `예상 글자 X 의 녹화가 없습니다` | 목록의 글자 X가 CSV에 없음 | X 녹화 또는 글자 이름 오타 확인 |
| `예상 목록에 없는 글자` | 데이터에 목록 밖 글자가 있음 | 이름 오타(대소문자·공백) 확인 |
| `_other 가 없습니다` | 그 밖의 손 모양이 없음 | 2.2절대로 `_other` 녹화 |
| `세션이 1개뿐` | 다른 날·조명 세션이 없음 | 둘째 세션 안내(권장) |
| `왼손과 오른손이 섞여` | 한 사람에서 두 손이 섞임 | 한 손으로 통일해 다시 |
| `시간 순서가 거꾸로` | 프레임 시간이 역전됨 | 해당 시도를 지우고 다시 |
| `형식 오류 N건` | 파일을 읽을 수 없음 | 9.4절 |

### 9.4 형식 오류가 났을 때

오류는 **파일 이름과 줄 번호만** 알려 주고 값은 보여 주지 않는다. 에이전트는 값을 보려고 파일을 열지 않는다. 팀원에게 파일을 직접 확인하게 하고, 흔한 원인을 안내한다.

| 오류 | 흔한 원인 | 조치 |
|---|---|---|
| `헤더가 녹화 도구 형식과 다릅니다` | 엑셀 등으로 저장해 열이 바뀜 | 파일을 편집하지 말고 **다시 녹화**(원본을 엑셀로 열지 않는다) |
| `CSV 안의 사람 ID가 폴더 가명과 다릅니다` | 폴더 이름을 바꿈 | 폴더 이름을 가명과 같게 되돌린다 |
| `CSV 안의 세션 ID가 파일 이름과 다릅니다` | 파일 이름을 바꿈 | 파일 이름을 `<세션>.csv`로 되돌린다 |
| `읽을 수 없는 줄입니다` | 줄이 잘리거나 손으로 수정함 | 그 파일을 새로 녹화 |

### 9.5 학습 PC 쪽 에이전트(데이터를 받은 뒤)

1. 받은 CSV를 `Tools/SignData/raw/<가명>/<세션>.csv`에 둔다. Git 제외를 확인한다(`git check-ignore -v`).
2. 전원 점검: `Check-SignRecording.ps1`(옵션 없이). 종료 코드 0이어야 학습으로 간다.
3. 기준선 측정: `Measure-SignKnn.ps1 -Sealed <봉인 가명>`(Sign-Fingerspelling.md 2부 A-2).
4. 관절 MLP 학습: `train_mlp.py ... --device cpu`. **4부 7절 실측에서 관절 MLP는 GPU보다 CPU가 빨랐다.**
5. **봉인 평가자는 학습·모델 선택에 쓰지 않는다.** 최종 평가는 모델을 다 고른 뒤 한 번만.
6. 결과는 **요약 숫자와 표**만 보고한다. 좌표·원본 행은 보고서에 넣지 않는다.

### 9.6 에이전트가 확인할 수 없는 것 (사람이 확인)

| 항목 | 이유 |
|---|---|
| 손 모양이 사전 영상의 글자와 맞는지 | CSV는 좌표뿐. 수어 전공자·검수자 확인 필요 |
| 조명이 다양했는지, 다른 날이었는지 | CSV에 없음. 기록지의 사람 기록을 본다 |
| 동의를 받았는지, 가명이 맞는지 | 개인정보 확인은 사람 몫 |
| Unity 화면이 문서와 같은지 | 이 문서는 코드 기준. 실기는 12절 |

## 11. 자주 묻는 질문

| 질문 | 답 |

## 12. 한계와 미검증

- **Unity 녹화 도구의 실제 화면 확인은 아직 하지 않았다.** 이 문서의 화면 문구와 순서는 코드(`SignRecorderWindow.cs`)와 Sign-Fingerspelling.md 3부에서 옮겼다. 첫 사용자가 다르게 보이는 곳을 알려 주면 고친다.
- 점검 도구(`Check-SignRecording.ps1`)는 **합성 데이터와 자동 테스트**(`Tests/SignRecordingCheck.Tests.ps1`)로만 확인했다. 실제 참여자 데이터로 돌려 본 적은 없다.
- 글자 5개는 **미확정**이다. 확정은 팀 모임 1회차(사전 영상 + 검수자).
- `_other` 권장 30회, 두 세션 분배 8+7회, 거리·위치 변주는 이 문서가 제안한 값이다. 문서 기준은 글자·`_other` 각 15회 이상이다.
- 손 추적의 좌우 거울 기준, Windows 빌드 실기는 웹캠 실기 확인 전까지 **미확인**이다.
- 데이터가 적어 결과는 일반화를 보장하지 않는다. 봉인 평가자 1명의 결과도 마찬가지다.

## 부록 A. CSV 형식 (에이전트용, 읽는 용도가 아니라 이해용)

한 줄 = 한 프레임. 열은 73개이고 순서는 다음과 같다.

| 열 | 이름 | 내용 |
|---|---|---|
| 1~4 | `person, session, trial, label` | 가명, 세션, 시도 번호, 글자 이름 |
| 5~6 | `frame, timestamp_ms` | 시도 안의 프레임 번호, 시간(밀리초) |
| 7~8 | `width, height` | 카메라 영상 크기 |
| 9~10 | `handedness, handedness_score` | `Left`/`Right`, 신뢰도 |
| 11~73 | `x0,y0,z0 … x20,y20,z20` | 손 관절 21개의 좌표(정규화) |

- 파일 위치: `Tools/SignData/raw/<가명>/<세션>.csv`. CSV 안의 `person`은 폴더 이름과, `session`은 파일 이름과 **같아야** 한다.
- 시도 하나 = 같은 `(session, label, trial)`의 프레임들. 유효 프레임이 10개 미만이면 학습에서 쓰지 않는다.
- 이 파일의 내용은 개인 데이터다. 에이전트는 **열지 않는다**(9.1절).
