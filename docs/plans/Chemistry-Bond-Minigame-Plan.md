# 화학과 전공자 미니게임 기획서 — 결합 설계실 (루이스 구조 · 분자 모양 · 극성)

버전 v0.5 · 작성 2026-11-26 · 갱신 2026-11-27 · 상태: 구현됨(브랜치 `feature/chem-bond-designer`) · Codex 독립 검증 2회 반영(v0.1: 0/5/3, v0.3: 0/8/3, 12절)

## 0. 한 줄 요약
화학과 **전공자(경험자)** 모드에서 기존 "분자 모형 조립"(원자 개수 맞추기)을 대신해, 원자 사이에 **단일·이중·삼중 공유결합**을 놓아 루이스 구조를 완성하고, **분자 모양(VSEPR)** 과 **극성**까지 판정하는 미니게임. 틀리면 **코드가 고정한 사실 해설** 아래에 **AI 교수의 맞춤 코멘트**가 붙고, 모양 문항에 답하면 분자가 **3D로 회전**하며 실측 결합각을 보여 준다. 비전공자는 지금 게임을 그대로 쓴다.

**역할 분리 원칙**: 정답·점수·가능한 혼동·결합각은 전부 코드가 정한다. 화면의 **사실 줄은 항상 코드 문장**이다. AI는 사실을 새로 말하지 않고, 학생 답에 맞춘 말투·격려 코멘트만 쓴다. 사실 단어·숫자가 섞인 AI 응답은 버린다. AI가 없거나 늦으면 코드 해설만 나온다.

## 1. 왜 이 게임인가
- 기존 `MoleculeBuilder`는 "H2O = H 2개, O 1개"처럼 **분자식 읽기**까지만 다룬다. 전공자에게는 쉽다.
- 공유결합 → 비공유 전자쌍 → 전자 영역 수 → 모양 → 극성은 일반화학 1학기 핵심 흐름이다. **3절 표의 고정 뼈대와 결합 수 규칙(H 1, C 4, N 3, O 2) 안에서** 정답이 하나로 정해져 코드로 판정·테스트할 수 있다(임의의 분자 일반에 대한 주장은 아님).
- 화면에 원자·결합선·전자쌍이 바뀌고 3D로 도는 과정이 보여 발표 화면으로도 좋다.

## 2. 게임 흐름

```
소개(교수 대사) → 분자 5개 × [① 결합 놓기 → ② 모양 고르기 → (3D 공개와 함께) ③ 극성 고르기] → 결과(게임 안)
```

### ① 결합 놓기 (핵심)
- 원자는 정해진 뼈대 위치에 미리 놓여 있다(예: HCN은 H – C – N 가로 배치).
- 원자 사이 **결합 자리를 클릭할 때마다 0 → 1 → 2 → 3 → 0**(우클릭은 역순). 선 개수로 표시.
- **첫 제출 전에는 정답 신호를 주지 않는다.** 원자 옆에는 현재 결합 수(예: `3`)만 숫자로 보인다. 필요한 결합 수는 전공자가 아는 지식으로 본다.
- **첫 제출이 틀리면** 그때부터 힌트를 켠다: 원자마다 `부족 / 정확 / 초과` 글자와 색(노랑·초록·빨강)을 함께 표시하고, 가장 먼저 틀린 원자 하나에 대한 코드 설명 한 줄을 보여 준다. 이후 맞힐 때까지 다시 제출할 수 있지만 결합 점수는 없다.
- **비공유 전자쌍은 결합이 맞게 완성된 뒤에만** 표시한다. 계산식 `(원자가 전자 − 결합 차수 합) / 2`는 중성 분자·형식 전하 0·모든 원자 옥텟(H는 2) 조건의 완성 구조에서만 성립하므로, 미완성·초과 상태에서는 표시하지 않는다.

### ② 모양 고르기
- 기준 원자를 강조하고 5지선다: 직선형 · 굽은형 · 삼각평면형 · 삼각뿔형 · 정사면체형.
- 중심 원자가 둘인 에텐·에타인은 **"강조된 C 원자 주변의 모양"** 을 묻는다고 문항·표·강조를 통일한다.
- **이원자 분자(N2, O2)는 ②를 출제하지 않는다.**
- 한 번만 고른다. 답하면 정오와 코드 해설을 보여 주고 곧바로 3D 공개와 ③이 함께 나온다(4.1절).

### ③ 극성 고르기
- 극성 / 무극성 2지선다, 한 번만 고른다. **3D 분자를 보면서 고른다**(대칭을 눈으로 확인하는 것이 학습 목표).

### 점수와 판정
- 문항별 1점: ① 결합(첫 제출 정답일 때만), ② 모양(이원자 분자는 없음), ③ 극성. 점수는 **각 문항에 답한 순간 확정**한다.
- 만점은 출제된 분자에 따라 13~15점이므로 **비율로 판정**: 만점의 **85% 이상 Delta 2, 60% 이상 Delta 1, 미만 Delta 0** (잠정, P3 실기로 조정).
- 전체 제한 시간 150초(잠정). **타이머는 멈추지 않는다**(3D 공개 포함). 입력은 남은 시간이 0보다 클 때만 받고, 한 프레임 안에서는 **입력 처리 → 시간 판정** 순서(같은 프레임의 제출은 인정). 시간이 끝나면 진행 중인 분자의 확정된 점수는 유지하고 나머지 문항은 0점.
- Delta 0이면 기존 `ExplainFailure`로 "결합 수 세는 법 / 전자 영역 세는 법 / 대칭과 상쇄" 가이드를 보여 준다.

### 2.4 해설: 코드 사실 줄 + AI 코멘트 (기본 범위)
기존 강의 퀴즈(`LectureQuiz.cs` 245~265행)의 "코드 해설 즉시 표시 → AI 응답이 기한 안에 오면 추가" 흐름을 따르되, **AI가 사실을 바꾸지 못하게** 역할을 더 좁힌다.

**(1) 코드 사실 줄 — 정답의 유일한 기준, 항상 표시**
- 형식: `정답 삼각뿔형 · N 주변 전자 영역 4개(결합 3 + 비공유 전자쌍 1)` 처럼 정답과 코드가 계산한 사실만.
- 교수별 톤 2종의 고정 문장으로 작성하고 사람이 검수한다.

**(2) 가능한 혼동 — 단정하지 않는다**
- `BondPuzzle.PossibleConfusions(분자, 단계, 고른 답)`는 그 오답에서 **흔히 나오는 혼동 후보 0~2개**를 돌려준다. 오답 하나로 학생의 생각을 알 수는 없으므로 "~ 때문에 틀렸다"가 아니라 "**이런 점을 헷갈리기 쉬워요**"로 표현한다. 후보가 없으면 "미상"으로 두고 사실 줄만 보여 준다.

   | 단계 | 오답 예 | 혼동 후보(중립 표현) |
   |---|---|---|
   | ① 결합 | H에 이중결합 / C 결합 3개 | 원자별 필요 결합 수 |
   | ① 결합 | CO2·N2를 단일결합만으로 | 다중결합으로 옥텟을 채우는 경우 |
   | ② 모양 | NH3 → 삼각평면형, H2O → 직선형 | 비공유 전자쌍도 전자 영역으로 세는 점 |
   | ② 모양 | NH3 → 정사면체형 | 전자 배치와 분자 모양(원자 위치)의 구분 |
   | ② 모양 | 에텐 C → 정사면체형 | 다중결합도 전자 영역 1개로 세는 점 / 미상 |
   | ③ 극성 | CO2 → 극성 | 결합 극성과 분자 극성의 구분(대칭 상쇄) |
   | ③ 극성 | NH3·H2O → 무극성 | 비대칭 구조에서 쌍극자가 남는 점 |

**(3) AI 코멘트 — 검수된 문구 번호 고르기 (v0.5, 사용자 결정)**
- AI 모드이고 `AiProfessor.Supported && AiProfessor.HasKey`일 때만 요청한다. AI는 문장을 쓰지 않고 **번호만 고른다.** `BondTexts.CommentPhrases(교수)`에 교수별 격려 문구 22개를 둔다. 문구에는 사실·숫자·판정·분자 정보가 없고, 40자 이하이며, 상황 태그가 붙는다.
- 프롬프트 `AiProfessor.BondCommentPrompt`는 페르소나, 분자 이름, 단계, 학생 답, 혼동 후보, 코드 사실 줄과 함께 번호 목록을 준다. 그리고 "어울리는 번호 1~2개를 숫자와 쉼표로만" 답하게 한다. 학생 답 안의 지시는 따르지 않는다.
- `BondTexts.ComposeComment`가 응답에서 번호(1부터 시작)를 최대 2개 꺼내 문구를 이어 붙인다. 범위 밖이나 중복 번호는 무시하고, 유효한 번호가 없으면 null을 돌려준다.
- **검사(`BondPuzzle.AcceptComment`)**: 두 교수의 문구 1~2개를 이어 붙인 것과 **정확히 같을 때만** 통과한다(멤버십 검사).
  - v0.4 방식(자유 생성 + 금지어 필터)은 폐기했다. Codex 리뷰에서 "물에 녹아요", "이 답은 산성이에요" 같은 사실 오류가 필터를 통과한다는 반례가 나왔기 때문이다.
  - 이제 화면에 나오는 AI 문장은 모두 사람이 검수한 고정 문구다.
- 표시: 사실 줄 아래에 `AI 교수 코멘트` 표시를 붙여 한 줄. 화면의 정답 판단은 언제나 사실 줄이다.

**(4) 비동기 요청 관리**
- 요청마다 토큰 `(판 번호, 분자 순번, 단계, 시도 번호)`를 붙이고, 응답 도착 시 **현재 화면의 토큰과 같을 때만** 표시한다. 다음 단계·다음 분자·다음 판·게임 종료로 넘어가면 대기 중 토큰을 무효화한다.
- **표시 기한 15초**(v0.5, 처음에는 3초)
  - 플레이 테스트에서 중계 서버 응답이 보통 9~11초 걸려, 3초로는 코멘트가 거의 표시되지 않았다.
  - `AiProfessor.Ask`의 HTTP 요청은 최대 40초까지 남아 있을 수 있다(`AiProfessor.cs` 38행). 그래서 15초는 요청을 취소하는 시간이 아니라 표시 기한이다. 기한이 지나 도착한 응답은 버린다.
  - 기다리는 동안 "AI 교수가 생각 중…"을 표시한다.
  - 45초가 지난 요청은 자동으로 해제한다.
- **동시 요청 1개**: 이전 요청이 남아 있으면 새 요청을 보내지 않는다(그 오답은 코드 해설만). 한 판 최대 10회.
- 연습 모드·게임 종료 후 늦게 도착한 응답은 무시하고 예외를 남기지 않는다.

**(5) 연결 경로·고지 (정정)**
- AI 모드는 기본적으로 **팀 Cloudflare 중계 서버 → Gemini 무료 등급**을 쓰지만, 설정에 **개인 Gemini 키**를 넣으면 직접 호출하고, Gemini가 아닌 키는 **유료 FactChat 게이트웨이**로 간다(`AiProfessor.cs` 10~45행). 그래서 "항상 무료·서버 전용"이 아니다. 비용·키 정책은 기존 AI 모드 설정을 그대로 따른다.
- 보내는 내용은 분자·단계·학생 답·코드 사실뿐이고 플레이어 이름·사진·대화 기록은 넣지 않는다. AI 모드 안내에 "오답 코멘트를 위해 문제 정보가 외부 AI 서비스로 전송된다"를 한 줄 추가한다.
- 웹 빌드(`Supported = false`)·오프라인·오류 시 코드 해설만 나온다. 대회 시연은 네트워크에 기대지 않고, AI 코멘트 장면은 미리 녹화한다.
- 발표 포인트: **"AI가 채점하거나 사실을 말하지 않는다. 코드가 사실을 고정하고, AI는 학생 답에 맞춰 말을 건넨다. 그 경계를 테스트로 보장한다."**

## 3. 분자 목록 (1차 10개 중 매판 5개 무작위)

| 분자 | 뼈대 | 정답 결합 | 비공유 전자쌍 | 모양(기준 원자 주변) | 극성 |
|---|---|---|---|---|---|
| 물 H2O | H–O–H | 단일 2 | O 2쌍 | 굽은형 | 극성 |
| 암모니아 NH3 | N 중심, H 3 | 단일 3 | N 1쌍 | 삼각뿔형 | 극성 |
| 메테인 CH4 | C 중심, H 4 | 단일 4 | 0 | 정사면체형 | 무극성 |
| 이산화 탄소 CO2 | O–C–O | 이중 2 | 각 O 2쌍 | 직선형 | 무극성 |
| 질소 N2 | N–N | 삼중 | 각 N 1쌍 | (② 미출제) | 무극성 |
| 산소 O2 | O–O | 이중 | 각 O 2쌍 | (② 미출제) | 무극성 |
| 사이안화 수소 HCN | H–C–N | 단일 + 삼중 | N 1쌍 | 직선형(C 주변) | 극성 |
| 폼알데하이드 CH2O | C 중심, H 2·O 1 | 단일 2 + 이중 1 | O 2쌍 | 삼각평면형(C 주변) | 극성 |
| 에텐 C2H4 | H2C–CH2 | C=C 이중 | 0 | 삼각평면형(강조된 C 주변) | 무극성 |
| 에타인 C2H2 | H–C–C–H | C≡C 삼중 | 0 | 직선형(강조된 C 주변) | 무극성 |

- 위 10개는 고정 뼈대에서 결합 자리 0~3 전수 탐색 시 해가 정확히 1개(Codex가 두 번 확인. P1 테스트로 고정).
- **O2 모형 한계**: O=O 루이스 구조는 실제 산소 분자의 홀전자 2개와 상자성을 나타내지 못한다(분자 궤도 이론). O2를 맞힌 뒤 교수 해설 한 줄로 알려 주고, 발표 자료에 "루이스 모형 범위의 게임"이라고 명시한다.
- **1차에서 뺀 것**: 형식 전하가 필요한 분자(CO, O3), 공명 구조(NO3⁻, 벤젠), 옥텟 예외(BF3, SF6, PCl5), 이온.
- 명칭은 대한화학회 명명법과 일치(Codex 확인). 사람 검수는 별도로 받는다.

- 상태(힌트 켜진 뒤): 색 + `부족 / 정확 / 초과` 글자를 함께 표시(색각 이상 대응).
- 결합 자리 클릭 영역은 선보다 넓게(최소 44px), 작은 창에서 실기 확인.
- 결합선: 얇은 막대를 `NovelUI.RotateAround`로 회전해 그린다(`GUIUtility.RotateAroundPivot` 금지). 이중·삼중은 평행선 2·3개.

### 4.1 3D 회전 보기 (기본 범위)
- **언제**: ② 모양 문항에 답하는 즉시(정오 무관) 왼쪽 판이 3D 보기로 바뀌어 회전하고, **같은 화면에서 ③ 극성을 고른다**. 이원자 분자는 ① 정답 직후 같은 방식. 타이머는 계속 흐르므로 공개 시간을 사고 시간으로 악용할 수 없다. ③에 답하면 다음 분자로 간다.
- **Completed 화면**: 이번 판 분자 5개를 작은 3D 갤러리로 보여 준다(한 번에 하나만 크게 회전, 나머지는 정지 썸네일 — 그리기 비용 제한).
- **좌표는 코드가 계산**(`MoleculeGeometry.cs`, 순수 C#). 분자별로 **실측 대표값과 출처**를 표로 고정한다.

  | 분자 | 표시 각(정의) | 값 | 출처 |
  |---|---|---|---|
  | CH4 | H–C–H | 109.5° | 정사면체 |
  | NH3 | H–N–H | 약 107° | NIST CCCBDB |
  | H2O | H–O–H | 104.5° | NIST CCCBDB |
  | CH2O | H–C–O / H–C–H | 약 121.9° / 약 116° | NIST CCCBDB |
  | C2H4 | H–C–C / H–C–H | 121.2° / 117.6° | NIST CCCBDB |
  | CO2, HCN, C2H2 | 결합 원자–중심–결합 원자 | 180° | 직선 |
  | N2, O2 | 없음 | — | 이원자 |

  - 삼각평면 분자는 "이상적 120°에 가깝지만 실제로는 다르다"를 짧게 보여 준다(교재의 이상화 각과 구분). NIST 값은 P1 착수 전 원문에서 다시 확인해 표에 출처 링크를 남긴다.
- **비공유 전자쌍 표시**: 반투명 영역(로브)으로 그리고 첫 등장 때 "**전자쌍의 대략적인 영역(VSEPR 모형), 실제 전자 위치가 아님**"을 한 줄 안내한다.
- **각 표시**: 굽은형·삼각뿔·정사면체·삼각평면은 호(arc)+숫자. 직선형은 호 대신 **직선 보조선과 `180°` 글자**(투영에서 호가 퇴화하므로). 이원자는 각 표시 없음.
- **그리기**: Unity 3D 오브젝트·카메라 없이 IMGUI 위에서 직접 투영한다. Y축 회전 + 고정 X축 기울기 → 원근 투영 → 원자와 결합(중점 깊이 기준)을 **함께 깊이 정렬**해 뒤에서부터 그림. 가까운 원자일수록 크게·밝게. 결합선은 4절과 같은 막대이고, 원자 원 안쪽으로 들어가는 부분은 원 반지름만큼 잘라 그린다. 깊이 정렬만으로 완벽한 교차 처리가 안 되는 경우는 X축 기울기 고정과 드래그로 시점을 바꿔 완화한다.
- **조작**: 3D 보기와 갤러리에서 마우스 드래그로 회전. 드래그 중에도 타이머는 흐른다.
- 새 에셋·셰이더·패키지 없음. 원자 최대 6개.
- 대안으로 Camera + RenderTexture 실제 3D를 검토했지만 IMGUI 게임 구조·Canvas 배율과 맞추는 비용이 커서 제외.

## 5. 교수 대사 (기존 2인 톤 유지)
- **정도윤 교수**(걱정 많은 안전 지킴이): "삼중결합도 결합 수는 3이에요. 서두르지 말고 원자마다 세어 봐요."

## 6. 연결 방식 (코드 변경 최소화)
- `MiniGames.Create`의 `case MiniGameKind.Molecule:`을 `experienced ? new BondDesigner(theme, professor) : new MoleculeBuilder(theme)`로 분기(`GameController`가 이미 `experienced`를 전달함).
  - 스토리: 화학과 챕터 1에서 **경험자**를 고른 플레이어에게 자동 적용.
  - 연습 모드: 기존 "비전공자 / 전공자" 토글로 바로 진입.
- 전공자일 때 제목은 게임 안에서 "결합 설계실"로 표시(테마 `Title`은 공유하므로 덮어쓰지 않음).
- 챕터 1 나레이션("분자식대로 원자 조립하기래")은 경험자용 문장을 따로 둘지 10절 결정 사항.
- 전공자는 `MiniGame.Easy = false`이므로 감속 없음.
- **AI 모드 전달 (정정)**: 강의 퀴즈와 같은 위치에 한 줄씩 추가한다.
  - 스토리(`GameController.cs` 472행 부근): `bond.ConfigureAi(aiMode, S, affection)` — 현재 스토리·현재 호감도.
  - 연습(`GameMenus.cs` 540행 부근): `bond.ConfigureAi(aiMode, Stories.All[practiceFaculty], 0)` — **선택한 학과 스토리·호감도 0**. 교수 인덱스는 `MiniGames.Create`에 넘긴 연습용 교수 값(`practiceProfessor`)을 쓴다.
  - `GameAiMode.cs` 머리 주석 "Minigames are unchanged"는 예외(강의 퀴즈·결합 설계실)를 적도록 고친다.
- **결과 표시**: 연습 모드는 완료 후 `EndPractice`로 바로 돌아가 교수 결과 대사가 생략되므로, 점수·문항별 정오·해설 요약을 게임 안 Completed 화면에 보여 준다.
- **저장·중도 종료**: 기존 미니게임처럼 게임 내부 상태는 저장하지 않는다. 도중에 나가거나 이어하기로 돌아오면 처음부터 다시 한다. 대기 중인 AI 요청은 무효화된다.

## 8. 검증 계획
### P1 순수 로직 테스트 (`Tests/BondPuzzle.Tests.ps1`, Unity 없이)
- 10개 분자 각각 결합 자리 0~3 전수 탐색 시 해가 **정확히 1개**이고 표의 정답과 같다.
- 완성 구조의 비공유 전자쌍·전자 영역·모양·극성이 표와 같다. 미완성·초과 상태에서는 전자쌍을 돌려주지 않는다.
- 결합 순환(정·역), 첫 제출 전 힌트 없음·첫 오답 후 힌트, 결합 점수는 첫 제출만, 이원자 ② 미출제, 만점 13~15 비율 경계(85%·60%), 시간 종료와 같은 프레임 제출 순서, 타이머가 3D 보기 중에도 흐름.
- 가능한 혼동: 모든 분자 × 단계 × 오답에서 후보 0~2개, 정답에는 없음, 모든 사실 줄·힌트 문장이 교수 2톤으로 존재. `BondTexts.Replies`가 2교수 × 3 Delta이고 비어 있지 않다.
- **AI 코멘트** `ComposeComment`/`AcceptComment`
  - 문구: 개수, 길이, 금지어(사실 단어·숫자·라틴 문자·"녹"·"산성"·"염기")가 없는지.
  - 번호 파싱: 2개, 1개, 범위 밖, 중복, 3개 이상, 숫자 없음.
  - 멤버십: 문구 1~2개 조합만 통과하고, "물에 녹아요"·"이 답은 산성이에요"는 거절.
- **요청 토큰**: 단계·분자·판 전환 시 이전 토큰 무효, 기한(15초) 경계, 동시 요청 1개, 판당 10회 한도.
- **3D 좌표**: 결합 길이 양수, 각 분자의 표시 각이 4.1절 표값과 ±0.5° 이내, 직선 분자 180°, 회전 후 원자 간 거리 보존, 깊이 정렬 순서.

## 10. 결정 사항 (팀)
1. **적용 범위**: 스토리 챕터 1의 경험자 게임을 교체할지, 연습 모드 전용으로 둘지.
2. **비공유 전자쌍**: 완성 후 자동 표시(제안) vs 플레이어가 직접 배치.
3. **단계 구성**: 결합 + 모양 + 극성(제안) vs 결합만.
4. **분자 목록**: 3절 10개 확정.
5. **제한 시간·판정 비율**: 150초 · 85%/60%(잠정, 타이머 무정지 기준).
6. **힌트 정책**: 첫 오답 후 힌트(제안) vs 힌트 없음 vs 힌트 사용 시 감점.
7. **경험자용 챕터 1 나레이션**을 따로 쓸지.
8. **화학 검수자** 지정.
9. **AI 코멘트 범위**: AI 모드에서만(제안) vs 일반 모드에서도.
