## 1부. 수어 지문자 인식 미니게임 계획서 (v1.0)

작성: Claude, 2026-11-26 · 검토: Codex 2회(v0.2 "수정 후 진행", v0.3 "수정 후 진행") 반영 · Antigravity 검토는 실행 환경 미설치로 미실시

### 0. 한눈에 보기

- 팀 모임 진행과 수동 작업은 수어 지문자 수작업 절차(3부)를 따른다.
- **만드는 것**: 웹캠으로 한국 수어 지문자 5개 내외를 인식하는 하이라이트 미니게임. 인터넷·유료 API 없이 PC 안에서 돈다.
- **우선순위**: ① 게임 + k-NN 기준선 완성 → ② 관절 MLP → ③ 그래픽카드 실험(이미지 CNN, 지식 증류, 증강·탐색)은 **시간 제한이 있는 선택 실험**.
- **발표 메시지**: "수어 지문자를 처음 배우는 사람을 위한 AI 체험". 팀이 직접 데이터를 모으고, 학습하고, 실험으로 비교해 모델을 골랐다. 번역기라고 하지 않는다.
- **현재 진행 (2026-11-26, main 병합)**: P0.5 손 추적 시험 화면(`c71fb25`), P1 인식 부품·녹화 도구(`8983518`), P3 하이라이트 미니게임 k-NN판(`d006ab4`) 구현. Unity 컴파일·단위 테스트 통과, **실기 미검증**. 남은 것: P0 글자 확정, 실기 확인, P2 녹화·측정. 사용법은 `AGENTS.md` 7절.
- **개발 방식**: Claude(설계·리뷰·통합) + Codex(구현) + Antigravity(구현·리뷰) 교차 검증. P1~P3에서 교차 리뷰로 발견·반영한 문제 27건(Codex→녹화 도구 5, Antigravity→핵심 로직 10, Antigravity·Claude→게임 화면 12). P0.5에서는 Claude 리뷰로 Codex 코드의 영상 반전 버그 등 3건과 컴파일 오류 1건을 고쳤다.

### 2. 이미 있는 것과 확인된 한계

- 영상 방향 규약: 얼굴 추적(`FaceMeshSolution.cs`)은 MediaPipe에 넘길 때 기본으로 상하를 뒤집고(`_flipVertically = true`), `videoVerticallyMirrored`와 180도 회전을 반영한다. 90/270도 회전은 지원하지 않는다. 손 추적도 같은 규약을 따른다.
- `com.unity.ai.inference` 2.6.1: UnitEye가 이미 ONNX를 `ModelLoader`·`Worker`로 실행한다(`GazeEstimationRunner.cs`). 새 모델의 연산자 호환·백엔드 동작은 미검증이다.
- 웹캠: `StopWebcamTracking()`(`GameController.GazeTest.cs`)은 추적 객체를 파괴하고 보정을 초기화한다. 4.4절.
- 미니게임: `MiniGameKind` 팩토리(`MiniGames.cs`)는 학과 스토리용이고 하이라이트 탭(`GameController.GazeHighlight.cs`)은 별도 진입 흐름이다.

### 3. 글자 선정 기준

최종 글자는 **국립국어원 한국수어사전의 지문자 영상으로 확인**하고, 가능하면 수어 전공자나 농인 1명의 검수를 받는다.
1. 한 손, 움직임 없는 정지 자세. 2. 손바닥·손등이 카메라를 향함. 3. 후보끼리 손가락 펴짐 패턴이 뚜렷이 다름(비슷한 쌍은 하나만). 4. 자음 위주 5개로 시작, 결과가 좋으면 8개까지.

### 4. 기술 구조 (게임 실행 쪽)

```
웹캠 ─▶ 방향 규약 적용(2절) ─▶ MediaPipe HandLandmarker [CPU] (관절 21개 + 왼손/오른손)
     ─▶ 미감지면 즉시 "손 없음" ─▶ 특징 정규화(C#) ─▶ 분류기 ─▶ 거절 규칙 ─▶ 시간 안정화 ─▶ 판정
```

#### 4.1 특징 정규화 (`SignFeatures.cs`, Unity 의존 없음)
- MediaPipe 정규화 x, y를 픽셀 비율로 되돌린다(x × 폭, y × 높이). **z는 쓰지 않는다**(단위가 달라 2D 좌표와 묶을 근거가 없음).
- 손목을 원점으로, 손바닥 크기(손목 ↔ 가운뎃손가락 시작 관절)로 나눈다. 최소값 미만이면 "손 없음".
- **좌우 통일 규칙(모든 입력에 공통)**: 왼손이면 관절 x를 뒤집어 오른손 기준으로 맞춘다. 이미지 CNN을 쓸 경우 같은 프레임의 손 이미지도 같은 규칙으로 좌우 반전한다. 이 결정적 변환 외에 **무작위 좌우 반전 증강은 하지 않는다**(손 방향이 의미일 수 있음). 왼손/오른손 판정이 흔들리면 최근 판정 투표로 정한다(1차 구현은 매 프레임 원시 판정 사용. 실기에서 흔들림이 확인되면 추가). 판정 라벨의 거울 기준은 P0.5 실기에서 확인해 문서에 적는다.
- 손 회전은 정규화하지 않는다. 손가락 마디 굽힘 각도(손가락당 2~3개)를 추가한다.
- 학습과 실행의 전처리 일치: 녹화는 원본 좌표·프레임 크기를 저장하고, Python 전처리와 C#에 같은 입력 10개를 넣어 출력 일치를 검사한다.

#### 4.2 분류기와 거절 규칙
- **기준선(필수)**: 순수 C# k-NN. 모델 파일 없이 녹화 좌표를 게임에 넣어 동작한다. 거리 상한과 1·2위 마진으로 거절한다(k-NN 점수는 확률이 아님). 거리 상한은 같은 글자·다른 시도 표본 간 최근접 거리의 95백분위 × 1.5(하한 0.05)로 자동 계산하며, 어느 글자든 서로 다른 시도가 2개 미만이면 계산하지 않고 상한 없이 동작한다(디버그 보기 "거리 상한 계산 불가(시도 부족)"). 그래서 글자마다 3회 이상 녹화한다.
- **본편 후보(선택)**: 관절 MLP 또는 증류된 학생 MLP를 ONNX로 내보내 Inference Engine으로 실행. 소프트맥스 값만 믿지 않고 마진 규칙을 같이 쓴다.
- "그 외 손 모양" 클래스: 손 펴기, 주먹, 다른 지문자, 전환 동작, 얼굴 가림. 손이 안 보이면 "손 없음" 상태(분류기에 넣지 않음).
- 실제 모르는 입력을 거절하는지는 P2 오인식률 측정으로만 판단한다.

#### 4.3 시간 안정화 (`SignVote.cs`, Unity 의존 없음)
- 최근 0.33초(타임스탬프 기준) 투표. 과반이고 거절되지 않았을 때만 "인식됨". 동률이면 "모름".
- "손 없음"이 섞이면 창을 비우고, 0.2초 이상 프레임이 끊기면 창과 유지 타이머를 초기화한다.
- 같은 글자 0.6초 연속 유지 시 정답. 수치는 설정값으로 두고 검증셋으로 조정한다.

#### 4.4 웹캠 공유와 복귀
- 진입 전 상태 기록: 시선 추적 사용 여부, 장치(웹캠/iPhone), 보정 완료 여부.
- 웹캠 시선 추적 중이면 "보정이 초기화된다" 안내 후 정지, 장치 해제 다음 프레임에 손 추적을 연다.
- 정상 종료·실패·취소 모두 같은 복귀 경로. 이전에 웹캠 시선 추적을 쓰고 있었다면 재보정 화면으로 안내(자동 복원 없음).
- iPhone 시선 추적은 그대로 둔다. 플레이어 사진 촬영과 동시에 카메라를 열지 않는다.
- 카메라 없음·권한 거부·손 모델(MediaPipe) 로딩 실패 시 "카메라 없이 보기" 모드로 바꾸고 게임은 멈추지 않는다. 학습 데이터로 분류기를 만드는 단계가 실패하면(데이터 없음·형식 오류) 참고 그림 목록도 없으므로 안내와 "돌아가기"만 제공한다.

#### 4.5 학교 PC(구형 CPU + 좋은 그래픽카드) 실행 대응
- **손 추적은 CPU로 구현한다**(얼굴 추적과 같은 방식). Windows에서 GPU 경로가 가능한지는 이번 범위에서 확인하지 않는다.
- 분류 모델은 Inference Engine CPU/GPU 백엔드를 둘 다 시도할 수 있게 하고, 실패하면 CPU로 떨어진다. 학교 PC에서 워밍업 후 **입력 준비부터 결과 읽기까지 실제 경과 시간**을 두 백엔드로 재서 빠른 쪽을 기본값으로 한다.
- 손 추적이 느리면 ① 처리 해상도 낮추기 ② 손 추적 빈도 낮추기(실제 갱신률을 측정해 판단) 순서로 한다. 손 영역만 다시 추적하는 방식은 좌표 복원과 추적 실패 재획득을 검증하기 전까지 선택 사항이다.

### 5. 게임 설계

- **진입**: 하이라이트 탭(P0.5 시험 화면을 발전). 화면 전환, 카메라 생명주기(4.4), 돌아갈 화면을 명세에 적는다. 사회복지학과 스토리 연결은 2차 결정.
- **진행**: ① 교수가 오늘의 지문자를 소개(손 모양 그림) ② 연습: 글자별 따라 하기, 관절 뼈대와 점수 막대 실시간 표시 ③ 도전: 제시 글자를 제한 시간 안에 차례로. 조합 문제는 고른 글자로 실제 만들 수 있는 것만.
- **AI 시각화**: 관절 점·선, 글자별 점수 막대, 유지 게이지, 처리 시간(ms), 사용 중인 모델·백엔드.
- **도움말**: 기본은 일반 안내. 특정 관절 조건을 실측해 둔 글자만 구체적 안내.
- **게임 화면 개인정보 안내**: "영상은 저장·전송되지 않고, 손 관절 위치만 이 PC 안에서 계산합니다". 녹화 도구는 게임 빌드에 들어가지 않는다.

### 6. 데이터 수집

#### 6.1 녹화 도구와 저장 항목
- **에디터 전용**(플레이어 빌드 제외). 저장 항목은 프레임마다 하나의 레코드로 **원자적으로** 묶는다: 프레임 ID, 타임스탬프, 원본 관절 좌표, 프레임 크기, 왼손/오른손 판정, 라벨, 사람 ID(가명), 세션 ID, 시도 ID, (동의 시) 손 이미지 파일명과 자르기 영역. 이미지와 좌표가 같은 프레임에서 나온 것이 보장되지 않으면 그 레코드는 버린다.
- **손 이미지 저장 규칙 (얼굴이 찍히지 않게 하는 방법)**
  - 촬영 구도로 막는 것이 1차 방어다: 카메라를 가슴·손 높이로 낮추거나 아래로 기울여 **얼굴이 아예 프레임 밖에 있게** 찍는다. 녹화 시작 전 미리보기로 얼굴이 안 보이는지 확인한다.
  - 2차 방어: 같은 프레임에서 얼굴 검출을 돌려, 얼굴이 검출되고 손 자르기 영역과 여유를 둔 영역이 겹치면 저장하지 않는다. **얼굴 검출을 실행할 수 없거나 실패하면 이미지를 저장하지 않는다**(좌표만 저장).
  - 3차 방어: 세션이 끝나면 저장된 이미지를 사람이 빠르게 훑어 얼굴·개인 정보가 보이는 것은 즉시 삭제한다.
  - 이 방법들도 얼굴 노출을 완전히 보장하지는 못한다. 그래서 이미지 저장은 별도 동의를 받은 사람만, 6.2의 보관 규칙을 지키는 경우에만 한다.
  - 자르기: 관절로 손 영역을 찾아 여유를 두고 정사각형으로 잘라 224×224로 줄인다. 시도마다 최대 10장, 시간 간격을 두고 저장한다.

#### 6.2 동의, 보관, 철회
- 동의는 항목별로 따로 받는다: ① 관절 좌표 수집 ② 손 이미지 수집 ③ 학교 PC 밖 반출(개인 PC) ④ 클라우드 학습 환경 업로드 ⑤ 학습된 모델의 게임 배포·대회 시연 사용.
- 동의서에 목적, 저장 항목, 보관 위치, 접근 가능한 사람, 보관 종료일, 철회 연락처를 적는다.
- 원본 위치: `Tools/SignData/raw/`(Git 제외, `.gitignore` 추가). **손 이미지는 Git·공용 드라이브에 올리지 않는다.** 클라우드 학습 환경은 ④에 동의한 사람의 데이터만 올리고, 학습이 끝나면 클라우드 사본을 지운다. ④ 동의가 없으면 클라우드에서는 좌표 데이터만 쓴다.
- 학교 PC에서 학습했으면 학습 후 학교 PC의 이미지 원본·캐시·중간 산출물을 지운다.
- **철회 시**: 그 사람의 원본(좌표·이미지)과 백업·캐시·체크포인트·클라우드 사본을 지운다. 그 사람 데이터로 학습된 모델은 폐기하고 남은 데이터로 다시 학습한다. 게임에 배포된 모델도 다음 빌드에서 교체한다.
- 보관 종료일(대회 종료 후 날짜)에 이미지 원본은 모두 지운다. 좌표 데이터 보관 여부는 10절에서 정한다.

#### 6.3 양, 나누기, 평가 규칙
- 녹화 단위는 "손을 한 번 올렸다 내리기(시도)". 글자당 사람별 15회 이상, 시도 사이에 거리·기울기·손을 바꾼다. 조명 2종 이상, 다른 날 세션 한 번 더.
- **참여 인원은 최소 5명, 가능하면 더 많이.** 그중 1명은 **봉인 최종 평가자**로 정하고 P2~P4 어떤 선택에도 쓰지 않는다. 나머지 인원으로 **한 사람씩 빼고 학습·검증을 돌아가며 하는 교차 검증**을 해서 한 명에게 맞춰지는 것을 줄인다.
- 측정은 프레임이 아니라 **시도 단위**로 한다. 모든 후보 모델이 같은 나누기, 같은 시드 3개, 미리 정한 학습 시간 한도, 같은 거절 규칙 형태, 같은 측정 방식을 쓴다.
- 실제로 쓸 수 있는 이미지 수(동의·얼굴 제외 후)를 사람·글자별로 보고한다. 데이터가 적으므로 학습 실험 결과는 **"작은 탐색 실험"**으로 표현한다.
- 봉인 평가자 1명의 결과는 일반화를 보장하지 않는다고 발표 자료에 명시한다.

### 11. 선택 실험: 그래픽카드 학습

#### 11.1 위치와 원칙
- 게임(P3)과 관절 MLP(P4) 이후에 하는 **선택 실험**이다. 기간을 미리 정하고, 끝나면 결과와 상관없이 멈춘다.
- 관절 MLP는 입력이 작아 CPU로도 충분할 것으로 예상하지만 실측으로 확인한다. 그래픽카드는 이미지 학습(방안 1·2)과 많은 실험 반복(방안 3)에 쓴다. 학습 시간과 그래픽카드 필요성은 실측값으로만 발표한다.
- 데이터가 적으므로 모든 결과는 "작은 탐색 실험"이며, 6.3 평가 규칙을 똑같이 따른다.

#### 11.2 방안 1: 손 이미지 CNN 파인튜닝
- 입력: 6.1의 손 이미지(4.1 좌우 통일 규칙 적용). 모델: ImageNet 사전학습 MobileNetV3-Small 또는 EfficientNet-B0, 출력층만 교체 후 미세 조정. 클래스: 지문자 N개 + "그 외".
- 증강: 밝기·대비·색조, 작은 회전(±15°), 크기·위치 이동, 흐림. 무작위 좌우 반전 없음.
- 게임 적용은 필수가 아니다. 학교 PC에서 손 추적 + CNN 종단 측정이 P3 갱신률 목표를 넘을 때만 후보로 둔다.

#### 11.3 방안 2: 교차 모달 지식 증류 (이미지 선생 → 관절 학생)
- 선생: 방안 1의 CNN. 학습이 끝나면 **고정**한다. 학생: 관절 특징 입력의 작은 MLP.
- 짝짓기: 6.1의 같은 프레임 ID로 이미지와 좌표를 짝짓는다. 짝이 없는 레코드는 증류에서 뺀다. 학생 쪽 증강은 짝 정합을 깨지 않는 것(작은 관절 잡음)만 쓴다.
- 손실 = α·정답 교차엔트로피 + (1−α)·T²·KL(선생‖학생). α, T는 교차 검증으로 고른다. 증류는 **학습셋에서만** 한다.
- 목표: 같은 평가 규칙에서 증류 없는 관절 MLP보다 나은지 확인. 낫지 않으면 증류 없이 간다(결과는 발표 자료).

#### 11.4 방안 3: 관절 증강과 설정 탐색
- 증강(학습셋에만): **2D 회전 ±15°**, 크기 ±10%, 관절별 작은 잡음, 손가락 길이 비율 변화. z를 쓰는 3D 회전은 좌표계·투영 검증이 필요하므로 이번 범위에서 제외한다.
- 탐색: 은닉층 크기·층 수·드롭아웃·학습률을 바꾸되, **후보 수와 학습 시간 한도를 미리 정한다**. 시드 3개 평균·편차를 기록한다.

#### 11.5 비교표 (발표 자료)
| 모델 | 입력 | 교차 검증 재현율(평균/최저 글자) | "그 외"·손 없음 포함 오인식률 | 학교 PC 종단 처리 시간(중앙값/95백분위) | 모델 크기 | 학습 시간(실측) | 표본 수 |
|---|---|---|---|---|---|---|---|
| k-NN | 관절 | | | | | 없음 | |
| 관절 MLP | 관절 | | | | | | |
| 관절 MLP + 증강·탐색 | 관절 | | | | | | |
| 이미지 CNN | 손 이미지 | | | | | | |
| 증류 학생 MLP | 관절 | | | | | | |

- 표에 올리려면 먼저 ONNX 내보내기·Unity 실행·학교 PC 종단 측정을 통과해야 한다(k-NN은 C# 실행).
- 게임용 모델은 **재현율·오인식률 기준을 넘는 것 중 학교 PC에서 가장 빠른 것**. 봉인 평가자 수치는 고른 모델 하나만 P6에서 별도로 적는다.

#### 11.6 학습 환경과 산출물
- Python 3.11, PyTorch(CUDA는 학습 PC 드라이버에 맞춤), torchvision, scikit-learn, onnx, onnxruntime. 버전은 P0.6에서 고정해 `Tools/SignTrain/requirements.txt`에 적는다.
- 코드: `Tools/SignTrain/`(데이터 로딩, 전처리, 방안별 학습, ONNX 내보내기, 비교표 생성). 데이터는 여기 두지 않는다.
- 산출물: 게임용 ONNX 1개(k-NN 채택 시 없음), 비교표(CSV·Markdown), 혼동표, 학습 곡선. 실험마다 설정·시드·데이터 나누기 해시를 기록한다.

### 0. 한눈에 보기

```
웹캠 영상 ─▶ MediaPipe 손 추적(CPU) ─▶ 손 관절 21개 좌표 ─▶ 특징 57개 ─▶ 분류기 ─▶ 거절 규칙 ─▶ 0.6초 유지 ─▶ 정답
                                                         (좌표 42 + 굽힘 각도 15)   (k-NN 또는 MLP)
```

| 단계 | 무엇을 "학습"하나 | GPU 필요 | 상태 |
|---|---|---|---|
| **A. k-NN 기준선 (필수)** | 학습 과정이 없다. 녹화 데이터 자체가 모델이다(가장 가까운 예시 5개의 투표) | 불필요 | ✅ 바로 가능 |
| **B. 관절 MLP (권장)** | 특징 57개 → 글자를 맞히는 작은 신경망을 학습 | 있으면 빠름(없어도 됨) | ✅ 학습·내보내기 스크립트 있음 (게임 실행 코드는 MLP 채택 시 🛠) |
| **C. GPU 실험 (선택)** | 손 이미지 CNN 미세 조정, 이미지 → 관절 지식 증류, 증강·설정 탐색 | **필요** | 🛠 이미지 녹화부터 필요 |

**순서 원칙:** A로 게임을 먼저 완성합니다. B는 A보다 나을 때만 게임에 넣습니다. C는 기간을 정해 두고 하는 발표용 실험입니다(계획서 7절, 11절).

### 1. 개념 — 꼭 알아야 할 것

#### 1.1 지도 학습과 우리 문제
- **지도 학습:** "이 손 모양 = 이 글자"라는 정답이 붙은 예시를 많이 보여 주고, 처음 보는 손 모양의 글자를 맞히게 하는 방법입니다.
- 우리 문제는 **분류**입니다. 입력은 한 프레임의 손 특징 57개, 출력은 글자 N개 중 하나 + "그 외(_other)"입니다.
- **"그 외" 클래스가 중요한 이유:** 분류기는 늘 무언가를 고릅니다. 아무 손 모양이나 정답 처리되지 않으려면 "글자가 아님"을 학습시켜야 합니다.

#### 1.2 특징(Feature)이 무엇인가
- 사진을 그대로 쓰지 않고 MediaPipe가 찾은 **손 관절 21개의 위치**를 씁니다. 손 위치·크기·피부색·배경의 영향을 줄이기 위해서입니다.
- 특징을 만드는 방법은 `Assets/Scripts/Sign/SignFeatures.cs`(게임)와 `Tools/SignTrain/sign_features.py`(학습용 Python)에 **똑같이** 구현되어 있습니다.
  1. 손목을 원점으로 옮깁니다.
  2. 손바닥 크기(손목 ↔ 가운뎃손가락 시작 관절)로 나눠 크기를 맞춥니다.
  3. 왼손이면 좌우를 뒤집어 오른손 기준으로 맞춥니다.
  4. 관절 21개의 x, y(42개)에 손가락 마디 굽힘 각도 15개를 더해 57개가 됩니다.
- **학습과 게임의 특징 계산이 조금이라도 다르면 모델이 망가집니다.** 그래서 두 구현이 같은 결과를 내는지 테스트(`Tests/SignFingerspelling.Tests.ps1`, `Tools/SignTrain/test_sign_features.py`)로 확인합니다.

#### 1.3 k-NN과 MLP의 차이
| | k-NN | MLP(다층 퍼셉트론) |
|---|---|---|
| 원리 | 새 입력과 가장 가까운 녹화 예시 5개를 찾아 다수결 | 특징 57개 → 은닉층(예: 128, 64) → 글자 점수를 내는 함수를 학습 |
| 학습 | 없음(데이터 저장이 전부) | 필요(수백~수천 번 반복 조정) |
| 장점 | 단순하고 설명 쉬움, 데이터만 바꾸면 바로 반영 | 데이터가 많아지면 더 정확할 수 있음, 실행 속도 일정 |
| 단점 | 데이터가 많으면 느려짐 | 학습·내보내기·게임 연동 작업이 필요 |
| 게임 반영 | CSV 복사 | ONNX 파일 + 실행 코드 |

#### 1.4 데이터 나누기 — 가장 많이 하는 실수
- **같은 사람의 데이터가 학습과 평가에 동시에 들어가면 점수가 부풀려집니다.** 모델이 손 모양이 아니라 "그 사람 손"을 외우기 때문입니다.
- 그래서 **사람 단위로 나눕니다.**
  - **교차 검증(Leave-One-Person-Out):** 한 사람을 빼고 나머지로 학습, 뺀 사람으로 평가. 모든 사람에 대해 반복해서 평균을 냅니다.
  - **봉인 평가자 1명:** 모델을 고르는 어떤 과정에도 쓰지 않고, 최종 모델을 **한 번만** 평가합니다.
- 프레임이 아니라 **시도(손을 한 번 올렸다 내리기) 단위로** 맞았는지를 셉니다.

#### 1.5 평가 지표
| 지표 | 뜻 | 잠정 기준 |
|---|---|---|
| 글자별 재현율 | 그 글자를 했을 때 맞게 인식한 비율 | 80% 이상 |
| 오인식률 | "그 외" 손 모양을 글자로 잘못 인식한 비율 | 10% 이하 |
| 5초 안 성공률 | 시도 시작 후 5초 안에 정답 처리된 비율 | 90% 이상 |
| 혼동표 | 어떤 글자를 어떤 글자로 헷갈렸는지 표 | 헷갈리는 쌍 찾기 |
| 처리 시간 | 학교 PC에서 한 프레임 처리 시간 | 분류 5ms 이하, 갱신 20회/초 이상 |

- 평균 재현율이 60% 미만이면 범위를 줄입니다(숫자 손 모양, 가위바위보 등). 60~80%면 헷갈리는 쌍을 빼고 다시 잽니다.

#### 1.6 과적합과 일반화
- **과적합:** 학습 데이터는 잘 맞히는데 새 사람은 못 맞히는 상태입니다. 데이터가 적을수록 쉽게 생깁니다.
- 막는 방법: 사람 수 늘리기(최소 5명), 시도마다 거리·기울기·손·조명 바꾸기, 증강(1.8), 작은 모델, 드롭아웃, 조기 종료.
- 우리 데이터는 적으므로 결과는 **"작은 탐색 실험"이라고** 발표합니다.

#### 1.7 그래픽카드(GPU) 학습의 개념
- **왜 GPU인가:** 신경망 학습은 거의 전부 **큰 행렬 곱셈의 반복**입니다. CPU는 강한 코어 몇 개(우리 PC는 6코어)로 순서대로 계산하고, GPU는 작은 코어 수천 개로 같은 계산을 **동시에** 합니다. 그래서 이미지처럼 큰 입력은 GPU가 수십 배 빠릅니다.
- **CUDA:** NVIDIA GPU에서 계산을 돌리는 플랫폼입니다. PyTorch를 **CUDA 버전과 맞는 빌드**로 설치해야 GPU를 씁니다.
  - 우리 GPU(RTX 5060 Ti, Blackwell, 컴퓨트 능력 12.0)는 최신 세대라 **CUDA 12.8 이상 빌드(cu128 또는 cu130)가** 필요합니다. TTS 작업에서 같은 PC로 cu128·cu130 둘 다 동작을 확인했습니다([TTS 문서 3.1절](TTS-Voice-Production.md)).
- **VRAM(그래픽 메모리):** 모델·입력·중간 계산이 모두 VRAM에 올라갑니다. 우리 GPU는 8GB입니다. 부족하면 `CUDA out of memory` 오류가 나며, **배치 크기**를 줄이면 해결됩니다.
- **배치(batch):** 한 번에 GPU에 넣는 예시 개수입니다. 크면 빠르지만 메모리를 많이 씁니다.
- **에폭(epoch):** 학습 데이터를 한 바퀴 다 보는 단위입니다. 보통 수십~수백 에폭을 돕니다.
- **정밀도:** fp32(기본) 대신 bf16/fp16(혼합 정밀도)을 쓰면 메모리를 절반 정도 쓰고 더 빠릅니다. RTX 50 시리즈는 bf16을 지원합니다.
- **우리 작업에 GPU가 꼭 필요한가:**
  - **관절 MLP(B):** 입력이 57개뿐이라 CPU로도 수십 초~수 분이면 끝날 것으로 **예상(❓ 실측 필요)**. GPU는 설정을 여러 번 바꿔 보는 탐색(C 방안 3)에서 시간을 줄여 줍니다.
  - **이미지 CNN(C):** 224×224 이미지 수천 장 × 수십 에폭이라 **GPU가 사실상 필수**입니다.
  - 발표에는 "GPU가 빨랐다"를 추측으로 쓰지 말고 **같은 조건의 GPU 대 CPU 실측 시간**만 씁니다(2.4절 측정 방법).
- **전이 학습(Transfer learning):** ImageNet(사진 100만 장)으로 미리 학습된 CNN(MobileNetV3, EfficientNet)을 가져와 **마지막 층만 바꿔** 우리 손 이미지로 조금만 더 학습시키는 방법입니다. 데이터가 적을 때 효과가 큽니다.
- **지식 증류(Knowledge distillation):** 무겁지만 정확한 "선생" 모델(이미지 CNN)의 출력 확률을 가벼운 "학생" 모델(관절 MLP)이 따라 하게 학습시키는 방법입니다. 게임에서는 가벼운 학생만 돌리면서 선생의 지식을 일부 얻습니다.

#### 1.8 데이터 증강
- 학습 데이터를 조금씩 변형해 양을 늘리는 방법입니다. **학습 데이터에만** 쓰고 평가 데이터에는 쓰지 않습니다.
- 관절: 2D 회전 ±15°, 크기 ±10%, 관절별 작은 잡음, 손가락 길이 비율 변화
- 이미지: 밝기·대비·색조, 작은 회전, 위치 이동, 흐림
- **무작위 좌우 반전은 하지 않습니다.** 수어는 손 방향 자체가 의미일 수 있습니다.

#### 1.9 ONNX와 Unity 실행
- **ONNX:** 학습한 모델을 프레임워크와 상관없이 실행할 수 있게 저장하는 표준 파일 형식(`.onnx`)입니다.
- PyTorch로 학습 → `torch.onnx.export`로 `.onnx` 저장 → Unity의 **Inference Engine**(`com.unity.ai.inference` 2.6.1, 프로젝트에 이미 설치, 시선 추적이 같은 방식으로 ONNX를 실행 중)으로 게임에서 실행합니다.

#### 2.4 학습 PC 소프트웨어 설치 (B·C 단계 전에 한 번)
아래는 Windows PowerShell 기준입니다. 가상 환경은 저장소 밖 `%USERPROFILE%\SignTrainVenv`에 만듭니다(4부와 같은 위치). 학습 PC 에이전트에게 맡길 때는 **4부 작업 지시서**를 그대로 쓰면 됩니다.

1. **NVIDIA 드라이버 확인**
   ```powershell
   nvidia-smi
   ```
   GPU 이름, 드라이버 버전, "CUDA Version"이 나오면 정상입니다. 안 나오면 NVIDIA 드라이버를 먼저 설치합니다.
2. **Python 3.11 설치** (계획서 11.6절 기준 버전)
   ```powershell
   winget install Python.Python.3.11
   py -3.11 --version
   ```
3. **가상 환경 만들기** (프로젝트별로 패키지를 분리)
   ```powershell
   py -3.11 -m venv $env:USERPROFILE\SignTrainVenv
   & $env:USERPROFILE\SignTrainVenv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   ```
4. **PyTorch (GPU 빌드) 설치** — RTX 50 시리즈는 cu128 이상. 버전은 `requirements.txt` 맨 위 주석을 따릅니다.
   ```powershell
   python -m pip install torch==2.15.0 torchvision==0.29.2 --index-url https://download.pytorch.org/whl/cu128
   ```
5. **나머지 패키지**
   ```powershell
   pip install -r <AI-ON 저장소>\Tools\SignTrain\requirements.txt
   ```
6. **GPU 인식 확인** — `True`와 GPU 이름이 나와야 합니다
   ```powershell
   python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
   ```
7. **버전 확인**: `Tools/SignTrain/requirements.txt`에 검증한 버전이 고정되어 있습니다. CPU 전용 설치 명령도 그 파일의 주석에 있습니다.
8. **저장소 받기**: `git clone` 또는 `git pull`로 AI-ON을 받습니다. 녹화 원본(`Tools/SignData/raw/`)은 Git에 없으므로 백업 저장소에서 따로 복사합니다.

**GPU 대 CPU 측정 방법(발표용):** 같은 데이터·같은 설정·같은 에폭으로 `--device cuda`와 `--device cpu`를 각각 실행하고, `--time-report`로 첫 에폭을 제외한 학습 시간과 최대 메모리를 기록합니다.

#### 2.6 녹화 PC → 학습 PC로 데이터 옮기기
녹화(웹캠·Unity)와 학습(GPU)을 다른 PC에서 하면 데이터를 옮겨야 합니다.

**게임 저장소(AI-ON Git)에 녹화본을 올리지 않습니다.**
- **기술적으로는 가능합니다.** 손 이미지 224×224 JPG는 장당 약 15KB라서, 5명 × 6클래스 × 15회 × 10장 = 4,500장이어도 70MB 안팎입니다. Git LFS로 올릴 수 있는 크기입니다.
- 그래도 올리지 않는 이유:
  1. **지울 수 없습니다.** Git은 과거 기록을 모두 보관합니다. 참여자가 동의를 철회해도 이미 받은 팀원 PC와 원격 기록에 남습니다. 기록을 다시 쓰는 것은 모든 팀원에게 영향을 주고, 완전히 지워진다는 보장도 없습니다.
  2. **공개 범위가 정해지지 않았습니다.** 저장소 공개 여부는 팀 결정 항목입니다. 공개되면 손 이미지(얼굴이 섞일 위험 포함)가 외부에 노출됩니다.
  3. **동의 범위를 넘습니다.** 계획서 6.2절은 손 이미지를 Git·공용 드라이브에 올리지 않기로 정했습니다. 동의서도 이 기준으로 받습니다.
  4. **팀원 모두가 받게 됩니다.** 학습과 관계없는 팀원 PC에도 참여자 데이터가 복사됩니다.
- 관절 좌표 CSV도 같은 이유로 지금은 Git에서 제외되어 있습니다(`.gitignore`). 좌표 커밋 여부는 팀 결정 항목입니다.

**권장 방법 (위에서부터 선호)**

| 방법 | 방식 | 철회 시 삭제 | 비고 |
|---|---|---|---|
| ① 암호화 USB·외장 디스크 | 녹화 PC에서 복사 → 학습 PC로 직접 이동 | 쉬움(사본 위치가 명확) | 가장 단순. BitLocker To Go 등으로 암호화 |
| ② 접근 제한 클라우드 폴더 | 학습 담당자만 접근하는 개인·학교 계정 폴더 | 가능(사본 삭제) | **동의 ④(클라우드) 받은 사람만**. 학습 후 클라우드 사본 삭제 |
| ③ 같은 네트워크 직접 전송 | 공유 폴더·`scp` 등으로 PC끼리 | 쉬움 | 학교망 정책 확인 |
| ④ 데이터 전용 비공개 저장소 | 게임 저장소와 **분리된** private Git 저장소 | 어려움(기록 남음) | 꼭 Git이 필요할 때만. 접근자 최소화, 철회 시 기록 정리 절차를 미리 정함 |

**어떤 방법이든 지킬 것**
- 옮긴 위치, 보관자, 보관 종료일을 결정 기록표(진행 대본 9절(3부))에 적습니다.
- 학습이 끝나면 학습 PC의 이미지 원본·캐시·중간 산출물을 지웁니다(계획서 6.2절).
- 폴더 구조는 녹화 도구와 같게 유지합니다: `raw/<가명>/<세션>.csv`(+ 이미지 폴더). 학습 PC에서는 `Tools/SignData/raw/`에 놓습니다.
- 학습 결과물 중 **모델 파일(.onnx)과 측정 요약표는 Git에 올려도 됩니다.** 참여자 원본이 들어 있지 않기 때문입니다. 다만 동의 ⑤(게임 배포)를 받은 사람의 데이터로만 학습한 모델이어야 합니다.

### 4. 튜토리얼 B — 관절 MLP 학습

> A가 끝나고 측정 결과가 있을 때 시작합니다. **A보다 나을 때만** 게임에 넣습니다.

#### B-0. 준비 상태

### 5. 튜토리얼 C — GPU 이미지 학습 실험 (선택, 🛠 이미지 녹화부터 필요)

> 게임 완성(A)과 B 이후, **정해 둔 기간 안에서만** 합니다. 결과는 발표 비교표용입니다.

#### C-0. 먼저 필요한 것
- 🛠 **손 이미지 녹화 기능:** 지금 녹화 도구는 관절 좌표만 저장합니다. 계획서 6.1절대로 손 영역을 224×224로 잘라 시도당 최대 10장, 같은 프레임 ID로 좌표와 짝지어 저장하는 기능이 필요합니다.
  - 얼굴이 찍히지 않게: 카메라를 손 높이로 낮추기 → 얼굴 검출 시 저장 안 함 → 세션 후 사람이 훑어 삭제
- 🛠 `train_cnn.py`(전이 학습), `distill.py`(증류), `augment_search.py`(증강·탐색)
- **이미지 수집 동의(②)를 받은 사람의 데이터만** 씁니다. 이미지는 Git·공용 드라이브에 올리지 않습니다.

#### C-1. 방안 1 — 손 이미지 CNN 전이 학습 (GPU 필수)
1. ImageNet으로 학습된 **MobileNetV3-Small** 또는 **EfficientNet-B0**을 불러옵니다.
2. 마지막 분류층을 "글자 N개 + 그 외"로 교체합니다.
3. 처음엔 앞부분을 고정하고 마지막 층만, 그다음 전체를 작은 학습률로 미세 조정합니다.
4. 증강: 밝기·대비·색조, ±15° 회전, 이동, 흐림(좌우 반전 없음)
5. 배치 32~64, bf16 혼합 정밀도로 VRAM 8GB 안에서 돌립니다(`out of memory`면 배치를 줄임).

#### C-2. 방안 2 — 지식 증류 (이미지 선생 → 관절 학생)
1. C-1의 CNN을 **고정**해 선생으로 씁니다.
2. 같은 프레임 ID로 짝지은 (이미지, 관절) 쌍에서, 학생 MLP가 정답과 함께 선생의 출력 확률을 따라 하도록 학습합니다.
   - 손실 = α × 정답 교차 엔트로피 + (1 − α) × T² × KL(선생 ‖ 학생). α·T는 교차 검증으로 고릅니다.
3. 게임에는 학생 MLP만 넣습니다(관절만 쓰므로 가볍습니다). 증류 없는 MLP보다 나을 때만 의미가 있습니다.

#### C-3. 방안 3 — 관절 증강·설정 탐색 (GPU로 반복 시간 단축)
- 은닉층 크기·층 수·드롭아웃·학습률 조합을 **미리 정한 개수만큼만** 시험하고, 시드 3개 평균·편차를 기록합니다.

#### C-4. 비교표 (발표 자료)
계획서 11.5절 표를 채웁니다. **ONNX 내보내기 → Unity 실행 → 학교 PC 측정을 통과한 모델만** 표에 올립니다. 게임용은 기준을 넘는 것 중 학교 PC에서 가장 빠른 것으로 고릅니다.

### 7. 자주 생기는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `torch.cuda.is_available()`가 False | CPU 전용 PyTorch 설치, 드라이버 문제 | 2.4절 4번 cu128 명령으로 재설치, `nvidia-smi` 확인 |
| `CUDA error: no kernel image is available` | GPU 세대(RTX 50)에 비해 오래된 PyTorch·CUDA 빌드 | cu128 이상 빌드로 재설치 |
| `CUDA out of memory` | 배치가 너무 큼 | 배치 크기 절반, bf16 사용 |
| 교차 검증 점수는 높은데 게임에서 안 맞음 | 학습·게임 특징 계산 불일치, 좌우 반전 규칙 차이 | `test_sign_features.py`와 PS 테스트로 일치 확인 |
| 특정 사람만 점수가 낮음 | 손 크기·습관 차이, 녹화 조건 | 그 사람 녹화 늘리기, 증강 |
| 두 글자가 계속 헷갈림 | 손 모양이 비슷함 | 혼동표 확인 후 한 글자를 다른 것으로 교체 |
| 아무 손이나 정답 처리됨 | `_other` 녹화 부족 | `_other`를 다양하게 더 녹화 |
| 측정 도구가 "사람 2명 이상 필요" | 봉인 제외 후 인원 부족 | 녹화 인원 늘리기 |

### 6. 교차 검증과 최종 평가

준비물: 최소 5명(봉인 1명 포함)의 동의된 녹화, PowerShell 5.1. 10~30분 이상. 결과는 `Tools/SignData/reports/`와 결정표에 기록한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Measure-SignKnn.ps1 -Folder Tools/SignData/raw -Sealed p05 -Seed 1701 -K 5
# 모델과 설정을 모두 고른 뒤에만 한 번 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/SignTrain/Measure-SignKnn.ps1 -Folder Tools/SignData/raw -Sealed p05 -Seed 1701 -K 5 -Final
```

1. `p05`를 봉인 가명으로 바꾸고 첫 명령을 실행한다. 교차 검증에서 봉인자를 제외한다. 봉인 제외 2명 미만이면 오류다. 계획의 목표 인원은 최소 5명이다.
2. 글자별 재현율 80% 이상, 그 외·손 없음 포함 오인식률 10% 이하, 5초 성공률 90% 이상이 잠정 기준이다. 현재 손 없음은 CSV에 없어 **미측정**, 5초 성공은 근사치다. 합격을 단정하지 말고 실기 점검을 함께 기록한다.
3. 평균 재현율 60% 미만이면 숫자 손 모양이나 가위바위보로 범위 축소를 검토한다. 60~80%면 혼동이 큰 쌍을 빼고 다시 측정한다. 결과는 작은 탐색 실험이다.
4. 최종 평가는 모델 선택 후 봉인 평가자로 한 번만 한다. 도구는 반복을 자동 차단하지 않으므로 기록자가 실행 여부를 기록한다. 봉인 1명의 결과는 일반화를 보장하지 않는다.

#### 단계 0. 시작 확인

- 기록: GPU 이름, 드라이버 버전, CUDA Version, VRAM

#### 단계 2. Python 3.11 가상 환경 (저장소 밖)

#### 단계 3. GPU 인식과 간단 성능 확인
```powershell
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```
- `True`와 GPU 이름이 나와야 합니다.
- 간단 성능 확인: 행렬 곱 4096×4096을 bf16과 fp32로 각각 50회 실행합니다. GPU와 CPU의 걸린 시간을 기록합니다(워밍업 1회 제외, `torch.cuda.synchronize()` 포함).
- 오류가 나면 학습 가이드 7장 표(`no kernel image`, `out of memory` 등)대로 해결하고, 해결 과정을 기록합니다.

#### 단계 3-2. C 단계(이미지 학습) 환경 미리 확인
- C 단계는 아직 데이터·스크립트가 없지만, 그때 막히지 않도록 환경만 확인합니다. 저장소에 새 파일을 만들 필요는 없습니다(임시 스크립트는 저장소 밖에 둠).
1. **사전학습 가중치 내려받기:** `torchvision.models.mobilenet_v3_small(weights="DEFAULT")`와 `torchvision.models.efficientnet_b0(weights="DEFAULT")`를 한 번씩 불러 캐시(`%USERPROFILE%\.cache\torch\hub\checkpoints`)에 저장합니다. 파일 이름과 크기를 기록합니다.
2. **GPU 메모리 확인:** 두 모델 각각 입력 `[32, 3, 224, 224]` 무작위 텐서로 `torch.autocast("cuda", dtype=torch.bfloat16)` 아래 순전파·역전파·옵티마이저 1스텝을 10회 돌리고, 스텝당 시간과 `torch.cuda.max_memory_allocated()`를 기록합니다. 배치 64도 시도해 VRAM 8GB 안에 들어가는지 적습니다.
3. **ONNX 내보내기 확인:** MobileNetV3-Small을 opset 17로 ONNX 내보내기 → onnxruntime(CPU)로 같은 입력 출력 비교(최대 오차 기록). Unity Inference Engine 2.6 호환 여부는 미검증으로 적습니다.

#### 단계 4. 학습 스크립트 GPU 검증
```powershell
python -m unittest discover Tools/SignTrain        # 전체 통과 확인 (CPU 기준 테스트)
```
- 테스트가 쓰는 합성 데이터 생성기로 학습 데이터를 만듭니다. 생성 방법은 스크립트 안내를 따릅니다.
