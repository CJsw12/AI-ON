| 글자 | 결과 |
|---|---|
| ㅂ, ㅇ | 수어자 5명(사전 포함) 모두 인식, 다른 손 모양을 이 글자로 받은 사례 없음 |

- ㄹ↔ㅌ은 손가락 펴짐·방향이 같아 2D 관절로 구분할 값을 찾지 못했다(손바닥 방향 같은 3D 정보 필요로 추정). ㅅ↔ㅈ은 ㅈ이 엄지를 더 벌리는 경향이 있으나 겹치는 사례가 있다.
- 게임 영향: 제시 글자를 맞히는 데는 문제없지만, 비슷한 글자를 해도 정답 처리된다. 대응 후보 ① "내 손에 맞추기"에서 ㅌ·ㅈ도 거절 예시로 받기 ② ㄹ·ㅅ를 헷갈릴 형제가 없는 글자로 교체 ③ 게임 안내에 "ㅌ·ㅈ과 비슷하다"고 명시. ㅎ 오인식은 두 손 감지(손이 겹치면 판정 안 함)와 엄지 방향 조건으로 줄일 수 있다.
- 남은 미검증: 실제 웹캠(조명·거리)과 Unity 실행, 영상 3개는 판정된 구간만 확인해 놓친 비율(재현율)은 대략적이다.

## 1. 왜 바꾸나

- 기존 계획은 마감 날짜가 없고 일정이 4주 이상을 전제한다. 녹화 5명×2세션, 동의서, 교차 검증, 봉인 평가, GPU 학습은 6일 안에 끝낼 수 없다(검토 3명 공통 high).
- 검토의 high 지적 대부분이 "팀 녹화 데이터"에서 나온다: 빌드에 참여자 좌표 CSV가 들어가는 개인정보 문제, 동의서 범위, 소표본 평가 기준, 오프라인 5초 지표 왜곡, 시험 데이터 혼입.
- 인식에 필요한 AI(손 관절 검출)는 MediaPipe가 이미 갖고 있다. 우리 데이터가 개선하는 것은 그 뒤의 글자 판정 단계뿐이며, 그 역할은 규칙과 "내 손에 맞추기"로 대부분 대신할 수 있다.

## 2. 범위

| 12/3에 한다 | 12/3에 안 한다 (졸업작품) |
|---|---|
| 한 손(오른손), 정지 자세 지문자 ㅂ·ㅇ·ㅎ·ㄹ·ㅅ(녹화 가이드 2.1의 잠정 글자) | 팀 녹화 세션, 동의서, 봉인 평가 |

| 연습·도전 게임, 참고 그림, 처리 시간 표시 | 사회복지학과 스토리 연결 |
| 팀원 실측(저장 없이 횟수만 셈) | 움직이는 지문자, 두 손 지문자 |

기존 계획의 녹화 도구·측정 도구·학습 스크립트·GPU 검증 결과와 녹화 가이드는 지우지 않고 그대로 둔다. 녹화 가이드의 글자 선정 이유(손 방향·모양 계열이 서로 다름)는 규칙 방식에도 그대로 유리하다.

## 3. 구조

```
웹캠 → MediaPipe HandLandmarker(관절 21개, 기존 HandLandmarkSource)
     → SignFeatures(기존, 특징 57개)
     → [내 손에 맞췄으면] 개인 k-NN  /  [아니면] 규칙 분류기
     → 판정 못 하면 "모름" → SignVote(기존, 0.33초 투표·0.6초 유지) → 게임
```

### 3.1 규칙 분류기 (`SignRuleClassifier.cs`, 새 파일, Unity 의존 없음)
- 입력은 기존 특징 57개를 그대로 쓴다. 뒤쪽 15개(`[42..56]`)는 손가락별 관절 각도 3개(π = 곧게 펴짐), 앞쪽 `[18],[19]`는 손목 → 가운뎃손가락 시작 관절 방향(정규화됨)이다.
- 손가락마다 **펴짐 / 굽힘 / 애매** 세 상태를 각도 합으로 정한다. 펴짐·굽힘 기준 사이를 "애매"로 두어 경계에서 판정이 튀지 않게 한다(히스테리시스 효과).
- 손 방향은 위 방향 벡터의 각도로 위·아래·옆 정도만 구분한다.
- 글자별 규칙표: `{ 글자, 손가락 5개 상태, 허용 방향 }`. 애매한 손가락이 규칙과 어긋나거나 일치하는 글자가 없거나 둘 이상이면 "모름"이다.
- 기준 각도는 상수로 두고 실기에서 조정한다. 규칙표는 국립국어원 한국수어사전 지문자 영상을 보고 확정한다.

**규칙표 초안** (녹화 가이드 2.1의 "그림에서 읽은 모양"을 옮긴 것, **사전 영상으로 미확인**)

| 글자 | 엄지 | 검지 | 중지 | 약지 | 소지 | 손 방향 | 추가 조건 |
|---|---|---|---|---|---|---|---|
| ㅂ | 굽힘 | 펴짐 | 펴짐 | 펴짐 | 펴짐 | 위 | |
| ㅇ | (조건 참고) | (조건 참고) | 펴짐 | 펴짐 | 펴짐 | 위 | 엄지 끝(4)–검지 끝(8) 거리 < 손바닥 크기 × 0.3 (동그라미) |
| ㅎ | 펴짐 | 굽힘 | 굽힘 | 굽힘 | 굽힘 | 위 | 엄지 끝이 엄지 시작 관절보다 위 |
| ㄹ | 굽힘 | 펴짐 | 펴짐 | 펴짐 | 굽힘 | 옆 | |
| ㅅ | 굽힘 | 펴짐 | 펴짐 | 굽힘 | 굽힘 | 아래 | 검지·중지 끝이 벌어짐 |

- 특징 배열에서 관절 i의 위치는 `[2i], [2i+1]`(손목 원점, 손바닥 크기 1)이고, 손바닥 크기는 손목(0)–가운뎃손가락 시작 관절(9) 거리다. 그래서 ㅇ의 거리 조건과 ㅎ·ㅅ의 추가 조건도 기존 특징만으로 계산된다.
- 주먹 계열(ㅎ)은 손목–관절 9 방향이 손 모양에 따라 흔들릴 수 있어(추정), 방향보다 엄지 끝 위치를 우선한다.

### 3.2 내 손에 맞추기 (`SignPersonalCalibration`, 새 파일, Unity 의존 없음)
- 게임 시작 시 선택 단계다. 글자마다 "이 모양을 2초 유지" → 첫 0.3초를 버리고 나머지 프레임을 3프레임 간격으로 저장한다(글자당 약 15개 표본, 손을 한 번 내렸다 올려 2회 받는다).
- 저장은 메모리에만 하고, 게임을 나가면 버린다. 파일·로그에 좌표를 쓰지 않는다.
- 분류는 기존 `KnnClassifier`를 재사용한다. 거리 상한은 이 사람의 1회차 ↔ 2회차 최근접 거리의 최대값 × 1.5로 정한다(`_other` 없음).
- 맞추기 중 규칙 분류기가 다른 글자로 강하게 판정하면 "이 모양이 맞나요?"를 띄운다(잘못된 표본 방지).
- 화면에 "인식 방식: 규칙 / 내 손"을 표시한다.

### 3.3 게임 흐름 수정 (기존 `SignGameSession`, `GameController.GazeHighlight.cs`)
1. 소개: 글자 목록과 참고 그림(`Assets/Resources/Sign/<라벨>.png`, 파일 이름 = 라벨, 출처·저작권 확인).
2. (선택) 내 손에 맞추기.
3. 연습: **"다음 글자" 버튼과 글자당 15초 제한을 추가한다.** 지금은 인식이 안 되면 도전으로 못 넘어간다(검토 Claude high, 코드 확인).
4. 도전: 제시 글자를 제한 시간 안에. 결과에 글자별 성공·시간.
5. 표시: 관절 뼈대, 유지 게이지, 감지 ms, **분류 ms**, **프레임 간격 95백분위**, 인식 방식.

### 3.4 기존 코드에서 함께 고칠 것 (검토 지적 중 이번 범위에 남는 것)
- 첫 프레임 대기와 실행 중 프레임 정지에 타임아웃을 두고, 넘으면 "카메라 없이 보기"로 바꾼다(Codex).
- 웹캠 요청 해상도 640×480 옵션(Gemini).
- `KnnClassifier`는 전체 정렬 대신 상위 k개만 고른다(표본이 적어 급하지 않음, 3명 공통).
- 오른손만: 왼손으로 판정되면 "오른손을 보여 주세요"를 띄운다. 좌우 판정이 실기에서 반대로 나오면 `SignHandedness` 거울 설정을 한곳에서 바꾼다.
- 빌드에 `StreamingAssets/SignData/*.csv`가 없어도 동작해야 한다(지금은 "학습 데이터 없음"). 규칙 분류기가 기본이 되면 해결된다.
