# AI 강의실 추천 미니게임 · 시선 선택 설계안

> 이 초안은 방 선택에 한정했던 이전 제안이다. 현재 방향은 [웹캠·iPhone 두 입력을 지원하는 시선 미니게임 구상](2026-11-04-dual-gaze-minigame-design.md)을 따른다.

- 상태: 검토용 제안. 승인 전에는 게임 코드, 패키지, 씬, 설정을 변경하지 않는다.
- 작성일: 2026-11-04
- 대상: AI-ON의 AI 강의실 추천 미니게임

## 1. 의도

경진대회 시연에서 플레이어가 화면의 강의실 후보를 실제 시선으로 골라 보는 입력 방식을 제공한다. 기능은 시선으로 화면의 정확한 좌표를 짚는 아이트래커가 아니라, 큰 방 카드 세 개 중 하나를 응시해 선택하는 간단한 상호작용으로 제한한다.

노트북은 Unity 게임을 실행한다. 기본 경로는 노트북 웹캠으로 시선을 처리한다. iPhone 연동은 기존 VTube Studio iOS 앱이 제공하는 눈 회전 데이터를 Wi-Fi UDP로 수신하는 방법을 우선 검토한다. 개발자가 iOS 앱을 직접 빌드하지 않아도 되는 경로다. 눈 회전 데이터가 방 카드 구분에 충분한지는 보정과 실기기 검증이 필요하다.

## 2. 의도와 확인된 선택

### 사용자가 확인한 내용

- 결과물은 상업 출시가 아니라 경진대회 제출물이다.
- 게임은 노트북에서 실행한다.
- 시선 입력을 AI 강의실 추천 미니게임의 방 선택에 붙이는 방향을 선택했다.
- 현재 사용할 개발 PC는 Windows뿐이다.
- iPhone을 센서로 연결하는 안은 더 멋질 수 있어 고려하고 있지만 필수로 정하지 않았다.

### 이 설계의 기본 제안

- 노트북의 기본 웹캠과 UnitEye를 첫 번째 추적 입력으로 사용한다.
- 시선 추적은 방 선택 단계에만 적용한다. 학습 데이터 검토, 모델 설정, 결과 확인에는 기존 마우스·키보드를 유지한다.
- iPhone 입력은 VTube Studio iOS 앱과 공식 Unity UDP 수신 예제를 이용하는 선택형 확장 목표로 둔다. 기기 호환성과 실제 방 선택 정확도를 확인한다.
- 기본 웹캠 경로는 iPhone 연결 없이 완주 가능해야 한다. iPhone은 단순 카메라 브리지 대신 ARKit에서 계산한 시선값을 Wi-Fi로 보내는 센서 역할을 목표로 한다.

## 3. 목표와 범위 밖

### 목표

- 첫 화면에서 카메라 시작을 명시적으로 선택하고 권한이 거부되거나 카메라가 없으면 마우스·키보드 모드로 진행한다.
- 짧은 사용자 보정 후 큰 방 후보 카드 세 개 중 하나를 시선으로 선택한다.
- 시선 위치 표시점과 카드의 진행 표시를 보여 줘서 입력이 잡히는지 사용자가 이해할 수 있게 한다.
- 일정 시간 안정적으로 응시했을 때만 선택하고, 시선이 흔들리거나 신뢰도가 낮으면 선택을 확정하지 않는다.
- 카메라를 이 미니게임에서만 사용하고, 영상이나 얼굴 특징을 저장하거나 외부로 보내지 않는다.
- 카메라 입력과 기존 마우스·키보드 입력을 함께 제공해 시연 실패와 접근성 문제를 완화한다.

### 범위 밖

- 정밀한 전체 화면 시선 커서, 의료·연구 수준의 아이트래킹, 시선 기반 텍스트 입력.
- 얼굴 감정 추정, 감정 분석, 영상 저장, 클라우드 분석.
- AI 추천 로직, 학습 데이터, 점수 계산을 시선 값으로 바꾸는 일. 시선은 사람의 후보 선택 입력에만 쓴다.
- 현재 모든 19개 미니게임에 시선 제어를 적용하는 일.
- 아이폰 카메라 영상을 노트북으로 전송하거나 얼굴 영상을 저장하는 일.
- 웹캠 기본 경로를 검증하기 전에 iPhone ARKit 앱, 무선 전송, iOS 서명·배포를 먼저 구현하는 일.
- Windows에서 iPhone을 웹캠으로 연결하기 위한 특정 유료 브리지 제품을 프로젝트의 필수 의존성으로 채택하는 일.

## 4. 현재 프로젝트 제약

- Unity 6000.3.23f1, Built-in Render Pipeline, 단일 `Main` 씬, 1280×900 고정 IMGUI 미니게임 화면.
- `GameController`가 `MonoBehaviour` 호스트이며, `MiniGame` 파생 클래스는 일반 C# 클래스다. 미니게임은 `MiniGames.Create`로 만들어지고 `GameController`에서 그려진다.
- 현재 패키지 목록과 `Assets/`에는 OpenCV for Unity, UnitEye, MediaPipe, Unity Inference Engine이 없다.
- 미니게임 가이드는 개별 미니게임에서 `MonoBehaviour`, 씬, 프리팹, Canvas를 쓰지 않도록 한다. 카메라 수명과 추론은 별도의 호스트 서비스가 맡아야 한다.
- 설정 메뉴가 열리면 미니게임 시계가 멈춘다. 추적 서비스도 메뉴가 열렸을 때 선택 이벤트를 내지 않도록 멈춤/차단 상태를 공유해야 한다.
- AI 강의실 추천 미니게임은 별도의 검토 초안으로 남아 있다. 그 설계가 승인되기 전에는 해당 미니게임 자체의 코드를 구현하지 않는다.

## 5. 대안과 추천

| iPhone ARKit 센서 앱 → 노트북 UDP 수신 | ARKit의 시선 추정값만 노트북 게임에 전달할 수 있어 시연 효과가 크고, 얼굴 영상을 전송하지 않아도 된다. ## 6. 제안된 플레이 흐름

1. **입력 선택** — 웹캠 시선, (확장 구현 시) iPhone ARKit, 마우스·키보드 중 사용 가능한 입력을 제공한다. 카메라나 센서가 준비되지 않으면 즉시 대체 입력으로 넘어간다.
2. **카메라 확인** — 사용자가 시작을 누른 뒤 웹캠 권한을 요청한다. 얼굴을 찾지 못하거나 권한이 거부되면 해결 방법과 대체 입력을 보여 준다.
3. **빠른 보정** — 화면의 왼쪽·가운데·오른쪽 안내 표식을 순서대로 응시한다. 보정 완료 여부를 표시하고 한 번 다시 할 수 있다.
4. **후보 선택** — 1280×900 작업 화면의 중앙에 세 방 카드를 가로로 배치한다. 카드 중심 시작안은 IMGUI 좌표 기준 (290, 420), (640, 420), (990, 420), 카드 크기는 약 300×340으로 잡고 실제 AI 강의실 화면에 맞춰 조정한다. 화면의 시선 점이 카드 안에서 약 0.7초 안정적으로 머물면 카드의 고리형 진행 표시가 차오르고 선택된다. 사용자가 시선을 떼면 진행 표시를 초기화한다.
5. **확인 및 계속** — 선택된 방을 강조하고, 기존 버튼/키 입력으로 확인하거나 다른 카드를 바라봐 바꿀 수 있게 한다.
6. **정리** — 미니게임 종료·취소·설정 진입 시 카메라와 추론을 중지한다. 얼굴 영상과 시선 기록은 저장하지 않는다.

숫자 값(응시 시간, 보정 표식 수, 신뢰도 임계값)은 초안의 시작점이며, 실제 노트북 카메라로 짧은 시험을 거쳐 고정한다. 마우스/키보드 조작은 항상 한 판을 끝까지 플레이할 수 있어야 한다.

## 7. 제안된 기술 경계

- `GazeTrackingHost : MonoBehaviour`가 입력 제공자, 추적 상태와 정규화된 시선 좌표를 관리한다. 기본 구현은 UnitEye 웹캠 제공자를 쓰고, 확장 구현은 UDP로 좌표를 받는 iPhone 제공자를 추가한다. `GameController`의 기존 `MonoBehaviour` 수명에 연결한다.
- 순수 C# 미니게임 클래스는 카메라 API를 직접 호출하지 않는다. 호스트가 제공하는 최근 시선 표본(좌표, 추적 가능 여부, 신뢰도)을 읽어 카드 영역과 응시 시간을 판정한다.
- `GameController.Update`와 메뉴/미니게임 상태를 사용해 서비스가 카메라를 쓰는 구간을 제한한다. 추론을 `OnGUI` 호출마다 돌리지 않는다.
- `UnitEye` 모델 번들과 MediaPipe 모델 파일은 빌드에서 로드되도록 포함한다. iPhone 확장에서는 영상 대신 보정된 정규화 좌표, 추적 유효 여부, 타임스탬프만 Wi-Fi UDP로 보낸다. 아이폰이 연결되지 않아도 게임은 웹캠 또는 마우스·키보드로 진행 가능해야 한다.
- 추적이 불안정할 때는 아무 선택도 하지 않고, 시선 점·신뢰도 안내와 마우스/키보드 입력을 유지한다.

## 8. 성공 기준

- Windows 노트북에서 Unity 6000.3.23f1 Editor와 독립 실행 빌드가 카메라 입력으로 작동한다.
- 세 개의 큰 방 카드 중 하나를 고르고, 사용자의 시선이 카드 경계를 흔들 때 임의 확정이 반복되지 않는다.
- 카메라 권한 거부, 카메라 없음, 얼굴 미검출, 낮은 조명, 사용자가 안경을 쓴 경우에도 대체 입력으로 한 판을 끝낼 수 있다.
- 카메라가 미니게임 외 화면에서 켜지지 않고, 영상 파일·개인 추적 로그가 만들어지지 않는다.
- 사용자는 현재 추적 상태와 선택 완료를 화면만 보고 이해할 수 있다.
- 기존 AI 추천 모델과 점수·스토리 흐름은 입력 선택과 독립적으로 유지된다.

## 9. 구현 전 확인할 작업

- 기존 AI 강의실 추천 설계 초안과 이 시선 입력 추가 설계를 각각 승인하고, 방 후보 카드 화면과 동작을 확정한다. 하나의 승인이 다른 문서까지 자동 승인하지 않는다.
- UnitEye의 정확한 Unity 6000.3.23f1 호환, Windows 플레이어 빌드, 카메라 선택, 모델 파일 배포를 별도 스파이크로 확인한다.
- 실노트북 웹캠에서 실제 응시 위치 편차와 조명/안경 상태를 측정해 보정·응시 시간을 조정한다.
- 웹캠 경로가 통과한 뒤 VTube Studio iOS 앱과 공식 Unity UDP 예제로 눈 회전 수신을 확인하고, 고정된 iPhone 위치에서 세 카드 보정을 시험한다. 성능과 앱 이용 조건이 맞으면 시연 옵션으로 추가한다. 직접 만드는 ARKit 앱과 클라우드 빌드는 그다음 대안이다.

## 10. 결정된 제안과 미결정 항목

- 이 문서는 AI 강의실 추천 게임 설계 초안과 별개의 입력 추가 기능이다. 각각 따로 검토·승인한다.
- 방 선택 목표는 한 줄의 큰 카드 3개이며, 중심 좌표와 크기는 현재 고정 1280×900 IMGUI 화면을 기준으로 한 시작안이다. 추천 게임의 최종 화면이 확정되면 카드 영역을 조정한다.
- 제출용 빌드에서 어떤 웹캠 모델을 쓸지, 최소 프레임 속도와 해상도 목표는 실측 후 정한다.
- iPhone ARKit 확장을 넣을지 여부는 웹캠 경로 완성 후 기술 검증과 남은 대회 일정에 따라 결정한다. 센서 iPhone 모델과 테스트 가능 여부도 확인해야 한다.
- UnitEye의 포함 모델 가중치와 제출 저장소 배포 조건은 고지문 및 대회 규정과 함께 확인한다.
